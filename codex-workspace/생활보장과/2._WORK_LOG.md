## 2026-10-11 · A 입문 첨부 시안형 UI 재구성

### 실제 변경

- 기존의 평면 3열 UI 렌더링을 시안 단계에 맞는 `01 시작 / 02 지도 대조 / 03 반려·수정 / 04 선정 완료` 상태 렌더링으로 교체했다. 상태는 기존 판정·저장 모델에서 파생하므로 퍼즐 로직을 재사용하지 않았다.
- [stage.css](src/leaflet-a/stage.css)를 새로 만들고 index.html에서 로드했다. 나무 책상 질감, 청록색 상단 단계 헤더, 좌측 업무 메모, 중앙 클립보드·클립·검토표, 우측 청록색 시험대, 종이 태그·홍보물·안내대 앞턱·분홍 반려 메모·선정 도장을 CSS/SVG로 구성했다.
- 공문 속 지도·관찰 썸네일과 증거 붙이기/기록 보기 버튼을 유지했다. 반려 단계에서 다른 견본 선택·지도 대조·비치·관찰·선정이 다시 가능하고, 완료 단계에서 결과 저장·다시 연습을 제공한다.
- PC·태블릿·휴대폰에서 책상 레이아웃을 세로 흐름으로 바꾸며 단계 헤더와 문서/시험을 유지했다. 터치 영역을 44px 이상으로 보정했다.
- 기존 browser.test를 시안형 렌더링의 버튼 배치와 완료 문구에 맞게 갱신했다. 검증 스크린샷을 6개 크기로 다시 생성했다.

### 검증 결과와 한계

Node 판정·복원 검사 18개 통과. Chrome/Chromium HTTP 브라우저에서 1440×900,1366×768,1024×768,768×1024,390×844,360×800 모두 반려→수정→완료→새로고침 복원 흐름을 통과했고, 키보드 Enter·Tab·화면 회전 흐름도 통과했다. 가로 넘침·44px 미만 표시 버튼·pageerror는 없었다. 시작·지도 대조·반려·완료 실제 화면은 `design/공문A_견본식별/구현검증/`에 저장했다.

실제 휴대폰 하드웨어와 사용자 재미 체험은 아직 미실시다. 첨부 이미지는 시각 기준으로만 사용하고 외부 이미지·폰트·에셋을 복사하지 않았다. 수정 예약은 해제했다.

## 2026-10-11 · A 입문 독립 플레이 구현

사용자가 계획대로 A 입문을 실제 플레이 가능하게 구현하고, 공문 중심 UI와 신규 로직을 사용하며 PC·모바일 독립 화면을 제공하도록 요청했다. 이전 코딩 금지는 이 요청으로 입문 범위에서 해제되었다. 중간·도전·B/C·본편 통합·공개 배포는 이번 구현에 포함하지 않았다.

### 실제 변경

- 생활보장과/src/leaflet-a/에 index.html, style.css, model.js, app.js, README.md를 새로 만들었다. 기존 퍼즐 엔진·상태·판정·게임 소스는 가져오거나 수정하지 않았다.
- 네 견본의 앞/뒷면·펼친 안/밖, 종이 지도와 QR 모양, 기준 지도·지도 대조, 40mm 앞턱 안내대를 자체 SVG/CSS로 표현했다. 정상 방향 자동 비치, 펼친 종이의 바로 비치, 비치 상태에서 펼침을 지원한다. 번호 가림은 실제 앞턱과 같은 물리 자료로 판단한다.
- 공문 선정과 조사 대상을 분리했다. 두 종류의 관찰 기록·중복 억제·기록 확대·보류/제외 표시·공문 첨부·해제·삭제 확인·반려 메모·부분 수정·선정 검토 도장까지 연결했다. 조사 중 자동 적합 체크나 강제 후보 순회·시간제한·벌점은 없다.
- 새 사건마다 후보 표시 순서를 섞고 같은 시도에서는 복원한다. 독립 자동 저장·부분 손상 복구·완료 결과 ID 유지·JSON 결과 다운로드·직전 완료본 보관 후 새 연습을 구현했다. 기존 게임 저장 키는 접근하지 않는다.
- PC 세 영역, 태블릿 두 영역과 자료, 모바일 공문/시험/자료 탭과 지도 세로 동시 비교를 구현했다. 클릭/터치·키보드·확대 닫기·음소거·동작 줄이기를 지원한다.
- 입문 테스트·실제 화면 증거와 [검증기록](design/공문A_견본식별/구현검증/검증기록.md)을 작성했다. 기존 정적 시안과 실제 PC·모바일 화면을 함께 연결했다. 계획·상태를 입문 실제 결과로 갱신하고 전체 난이도와 사용자 재미 미완료를 유지했다.
- 로컬 시험 서버는 기존 포트와 충돌해 8897로 변경했다. A 독립 폴더만 제공하며 localhost와 내부IP 192.168.35.67의 응답 문서가 A인지 확인했다. 공개 배포·방화벽 설정 변경은 하지 않았다.

### 검증 결과와 한계

Node 판정·관찰·복원 검사 18개 통과. Chrome/Chromium 154.0.8037.100의 HTTP 브라우저 플레이에서 1440×900,1366×768,1024×768,768×1024,390×844,360×800 모두 견본2 반려→견본4 부분 수정→새로고침→완료→새로고침과 근거 확대·Escape 닫기를 통과했다. 가로 넘침·44px 미만 표시 버튼·pageerror는 없었다. Tab 진입과 Enter로 전체 완료, 390×844에서 844×390 변경 후 완료 공문 유지도 확인했다. 키보드 검사 중 바로가기 링크의 숨김 방식을 수정했다. 상세 JSON과 스크린샷은 검증 폴더에 있다.

file:// 플레이 검사 후 최종 HTTP 경로로 검사했다. 제한된 네트워크 검사 환경은 허용된 로컬 실행으로 확인했다. 실제 휴대폰 하드웨어·iPhone Safari·Android Chrome·LAN 외부 단말의 접속·사용자 재미 체험은 미실시다. 자동 모바일 크기/터치 검사를 실제 사용자 체험으로 표현하지 않는다. 입문은 기능 구현 완료이며 전체 A와 재미 검증 완료는 아니다. 수정 예약은 해제했다.

## 2026-10-11 · A 구현 전 전체 계획 작성

사용자는 공문 중심 A에 대해 코딩 전 필요한 모든 계획을 요청했다. 모바일 질문 패널에서 한 답변 뒤 다른 질문이 사라진다는 설명을 받고 대안을 채팅에 표시했다. 사용자는 화면 범위·첫 문제 기본 규칙·독립 A+연결 명세·표와 정적 시안은 추천대로, 난이도는 입문·도전 모두 구현하며 진행에 따라 변화하도록 선택했다. 선택이 명확해 같은 범위의 확인을 다시 요구하지 않고 계획을 작성했다.

### 실제 변경

- [A 구현 준비 계획](design/공문A_견본식별/A_구현준비계획.md)을 진입 문서로 만들었다. 목표·상태·완료·진행·결정·검증 구조로 준비 항목·실행 단계·27개 기능 사례·기기·재미 체험 기준을 정리했다.
- [A 구현 전 전체 명세](design/공문A_견본식별/A_구현전_전체명세.md)에 입문→중간→도전 자료, 두 안내대·지도 이름·접힌 면·사용 가능한 입구의 차이, 원본·문구·에셋, 입력·화면·상태·관찰·첨부·판정·수정·저장·결과·새 구현 책임을 작성했다.
- 첫 문제 4견본·3조건·2근거는 사용자 선택 기준으로 유지했다. 중간 네 후보·도전 여섯 후보는 두 환경을 확인하는 세 근거를 사용하며 시간제한·숨은 조건·글씨 축소로 어렵게 하지 않는다. 난이도는 새 사건 시작 때만 정한다.
- 기본 상세 기획을 최신 문서와 연결하고 정상 비치 자동 배치, 펼친 안/밖 전환을 명확히 했다. 입력으로 제공하지 않는 비정상 비치를 숨은 반려 조건에서 제거했다.
- 내장 image_gen.imagegen으로 화면 상태·모바일·도전 정적 시안을 생성해 설계 폴더에 저장했다. 상태 시안은 중복 지도 근거 칸을 두 관찰 슬롯으로 부분 수정했다. 원본·프롬프트·수정 이유는 기존 이미지 제작 기록에 추가했다.
- 통합 계획·상태에 계획 완료와 다음 단계, 새 결과 링크를 반영했다. 새 TODO·DECISIONS·게임 소스·HTML은 만들지 않았다.

### 검토와 한계

사용자 선택과 문서 범위를 대조했다. 입문·중간·도전 후보 표에서 각 단계 적합 후보가 한 개이며 관찰·공개 조건으로 설명 가능한지 검토했다. 실제 입력으로 도달하는 상태, 조사/선정 분리, 불변 근거·부분 수정·저장/완료 중복 방지의 명세를 대조했다. 내장 이미지 결과의 주요 사물 가림·전화 노출·슬롯·탭·두 환경을 직접 확인했다. 계획·전체 명세·기본 기획·제작 기록의 로컬 링크 26개에서 누락 0개를 확인했고 활성 계획 최상위 항목을 확인했다.

이는 문서와 정적 시안 검토다. 기능 테스트·실제 치수 승인·기기 조작·재미 체험은 아직 실행하지 않았다. 생성 이미지의 일부 지도·날짜·본문은 실제 에셋으로 쓰지 않으며 명세의 원본을 따르도록 기록했다. 게임 코드·기존 계약·본편 연결·배포는 변경하지 않았다. 수정 예약은 해제했다.

## 2026-10-11 · A 기본 UI를 공문 중심으로 선택

사용자가 두 시안을 비교한 뒤 공문 중심이 더 좋다고 선택했다. A 상세 기획·통합 계획·상태 문서에 공문 중심 시안을 이후 화면 구체화의 기준으로 기록했다. 책상 중심 시안은 비교 자료로 보존한다. 상세 기획에는 공문·실물 시험·참고 자료의 구성 방향을 연결하고 실물 시험의 가독성을 유지하는 후속 설계 원칙을 제안했다.

사용자 선택이 세부 규칙·픽셀 치수·폰트·구현 착수의 일괄 승인을 뜻하지 않도록 구분했다. 갱신 문서에서 공문 중심 선택 상태의 일치를 확인했다. 이미지·게임 코드·HTML은 변경하지 않았으며 실제 플레이 검증은 미실시다. 수정 예약을 해제했다.

## 2026-10-11 · A 견본 식별 상세 기획 제안과 정적 UI 비교

사용자는 A부터 실제 자료·조작·재미·판정을 구체화하고 각 규칙 계획에 참고 게임 구현 방식과 UI 반영을 포함하도록 요청했다. 네 사전 질문 답과 이해 확인에서 실물 시험 중심, 한 사건의 핵심 발견 2~3개, 책상 중심·공문 중심 두 UI 비교, 정적 시안과 플레이 표를 선택했다. 게임 코딩은 하지 않는 범위다.

### 실제 변경

- [A 상세 기획](design/공문A_견본식별/A_견본식별_상세기획.md)에 요청 메모·본관 안내도·완성 견본 네 개·안내대·공문 초안을 제안했다. 펼치기·비치·지도 대조와 관찰 기록·선정·판정·부분 수정의 관계를 명세했다.
- 종이 안내가 없거나, 안내대에서 번호가 가리거나, 다른 건물의 지도를 담는 세 오답과 세 조건을 충족하는 한 견본을 제작자용 표로 정리했다. 성공은 모든 후보 방문이 아닌 적합한 선정과 같은 견본의 지도 대조·비치 기록 두 장에 둔다.

### 검증과 실제 상태

견본별 적합성 표와 공개된 사용 조건을 대조해 이 제안에서 적합 후보가 하나임을 확인했다. 정상 비치·근거 누락·관찰 대상 불일치·반려 후 수정 조건을 문서로 검토했다. 생성 시안과 참고 게임 화면을 직접 확인하고, 상세 기획·제작 기록·통합 계획의 로컬 링크 12개가 실제 파일로 이어지는지 확인했다. 정적 이미지의 상호작용 검증이나 사용자 재미 검증은 아니다.

책상 중심 UI를 추천했으며 UI 선택·문제 자료·세부 규칙·치수는 사용자 확인 대기다. 게임 코드·HTML·기존 에피소드 계약은 변경하지 않았다. 신규 TODO·DECISIONS 문서는 만들지 않았다. 구현·본편 연결·배포는 미착수이고 수정 예약은 해제했다.

## 2026-10-11 · 참고 게임 심층 분석과 공문 적용 후보 비교
