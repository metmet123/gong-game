# A 구현 준비 계획

작성일: 2026-10-11 · A 계획과 현재 구현의 진입 문서. 같은 날 사용자 요청으로 입문 독립 구현을 진행했다.

## 목표

공문 중심 UI에서 견본의 실물 시험·발견·선정·근거 첨부·검토·부분 수정을 하나의 플레이로 완성한다. 입문·중간·도전과 진행에 따른 난이도 변화를 구현 대상으로 포함한다. PC·태블릿·휴대폰에서 같은 판단과 완료 조건을 지원한다. 최우선 기준은 사용자가 시험으로 생각을 바꾸고 선택의 이유를 알아내는 재미다.

규칙·콘텐츠·버튼·상태·판정·저장·결과·에셋의 기준은 [구현 전 전체 명세](A_구현전_전체명세.md), 첫 문제와 참고 게임의 실제 방식·공개 화면은 [기본 상세 기획](A_견본식별_상세기획.md)에 있다. 수치·폰트·배치 시작값은 제안이며 실제 구현 화면에서 확인한다.

## 상태

- 사용자 선택: 공문 중심, 모든 화면 지원, 입문 첫 문제 4견본·3조건·2근거, 독립 A와 후속 연결 명세, 표·체크리스트·정적 시안.
- 난이도: 입문과 도전을 모두 구현 대상으로 선택. 중간 연결 단계와 구체적인 문제 자료는 전체 명세에 설계했다.
- 계획·정적 시안: 작성 완료. 선택한 기본 화면과 시작·조사·반려·완료·모바일 시안을 연결했다.
- 입문 코드·HTML·새 SVG/CSS 사물·저장·결과: 구현. PC/모바일 크기의 Chromium 자동 플레이 검증. 실제 휴대폰·사용자 재미 체험·중간·도전·본편 연결·공개 배포는 미실시.
- 플레이: [A 입문 독립 화면](../../src/leaflet-a/index.html) · [실행 방법](../../src/leaflet-a/README.md) · [구현 검증](구현검증/검증기록.md).
- 실제로 정해야 하는 후속 값: 화면 실측·조작/애니메이션 조정·사용자 체험 결과에 따른 단서 조정. 구현 전 기능 범위를 미정으로 남겨 둔 항목은 없다.
- 범위 외 연결 결정: 본편의 실제 해금 시점·재화 보상·통합 저장 API·부서 이동. A의 결과 의미와 연결 조건은 명세했으며 이 결정은 독립 A 구현을 막지 않는다.

### 예정 소스와 산출물

실제 구현 요청 후 생활보장과의 신규 독립 경로 src/leaflet-a/에 사건 자료·장면·상태·판정·화면·저장·결과·도움을 책임별로 둔다. assets/leaflet-a/에는 새 원본 에셋과 출처 목록을 둔다. 독립 실행 진입 파일과 검증 기록도 생활보장과 안에 둔다. 현재 파일·폴더의 실행 코드는 만들지 않았다.

브라우저가 같은 출처로 읽는 정적 페이지에서 저장·재개를 검증한다. 파일 직접 열기와 로컬/배포 주소가 동일한 저장을 공유한다고 전제하지 않는다. 본편 연결 전까지 루트 빌드·기존 게임·다른 부서 소스는 바꾸지 않는다.

## 결정

### 사용자 선택으로 유지할 범위

- 공문 중심과 실물 시험, 홍보물 제작·실제 공문 콘셉트.
- 첫 문제 4견본·3조건·2근거와 입문·도전 모두 구현.
- 게임 진행에 따른 난이도 변화, 독립 A 검증 후 후속 연결.
- 모든 화면 지원과 상태표·체크리스트·정적 시안.
- 기존 퍼즐 로직·E01 시안 폐기 범위와 원본 파일 보존.
- 계획 작성 당시에는 코딩 금지였다. 후속 사용자 요청으로 입문 독립 구현을 승인했다. 중간·도전의 범위는 전체 계획에 유지하되 이번 구현은 입문으로 제한한다.

### 이번 계획의 구현 기준과 조정 범위

- 입문 → 중간 → 도전은 새 사건 시작 때 결정한다. 진행 중 조건·난이도를 바꾸지 않는다.
- 도전의 어려움은 두 사용 환경·지도 관계·접힌 면에서 나온다. 시간 압박·작은 글씨·숨은 조건은 넣지 않는다.
- 클릭·탭·키보드로 완결하며 드래그는 선택 입력이다.
- 조사 후보와 선정 후보를 분리하고 관찰 기록을 불변으로 보존한다.
- 제출은 같은 견본의 실제 조건과 근거를 검사하며 정답 ID·방문 횟수로 통과시키지 않는다.
- 에셋 표시·기록 재현·판정에 같은 원본을 사용한다.
- 치수·애니메이션·체험 수치는 시작값이다. 사용자 승인 수치와 실제 검증 결과를 이후 명세에 따로 기록한다.
- 본편 보상·저장·API 연결은 실제 연결 단계에서 정한다. 이번에는 전달 의미와 검증 조건까지 계획한다.

### 기기·화면 확인

계획 기준 화면은 1440×900, 1366×768, 1024×768, 768×1024, 390×844, 360×800이며 실제 사용 가능한 기기의 크기와 브라우저 버전도 기록한다. 데스크톱 Chrome/Edge, Android Chrome, iPhone Safari를 확인 대상으로 계획한다. 실제 버전과 지원 결과는 구현 검증에서 기록한다.

마우스·터치·키보드, 화면 회전, 글자/화면 확대, 고정 탭과 기기 안전 영역, 문서 스크롤, 지도 대조 확대, 포커스 복원을 확인한다. 주요 단서가 작아서 안 보이거나 버튼이 다른 영역을 가리면 지원 화면에서 완료한 것으로 인정하지 않는다. 최소 화면에서는 서류의 세로 스크롤을 허용하되 가로 전체 넘침을 만들지 않는다.

### 사용자 재미 체험

입문 초기 확인은 새 사용자 2~3명으로 막힘을 먼저 찾는다. 보완 후 처음 보는 사용자 5명(PC 사용 3명·휴대폰 사용 2명)을 목표로 진행한다. 도전은 입문을 익힌 사람에게 새 자료로 이어서 체험시킨다. 실제 모집 상황이 다르면 수와 조건을 먼저 기록하고 기준을 다시 적용한다. 아래는 소규모 개발 판단 기준이며 통계적 만족도 추정으로 표현하지 않는다.

1. 목표 설명과 첫 화면만 제공하고 정답 경로를 안내하지 않는다.
2. 첫 의미 있는 행동·시험 중 발견·후보 변경 이유·막힘·제출 반복·근거 첨부의 부담을 관찰한다.
3. 완료 후 왜 그 후보인가, 생각이 바뀐 순간이 있었나, 반복 일처럼 느낀 부분은 어디인가, 더 해 보고 싶은가를 묻는다.
4. 힌트 사용·시간·반려 횟수는 보조 기록이며 플레이 보상·난이도를 바꾸지 않는다.
5. 개인 이름·연락처는 필요하지 않으며 체험 기록을 외부 분석 서비스에 전송하지 않는다.

입문 판단 기준 제안: 5명 중 4명이 60초 안에 조작 설명 추가 없이 첫 조사 행동을 시작하고 최종 선택 이유를 세 조건으로 설명한다. 3명 이상이 재미있는 순간을 구체적인 사물 변화·발견으로 말하고 재미 5점 중 4점 이상을 준다. 진행 소실·오판정·필수 단서 미노출은 한 건이라도 해결한다.

도전 판단 기준 제안: 5명 중 4명이 두 환경·접힌 면·지도 이름/입구 중 왜 추가 시험이 필요한지 설명하고, 3명 이상이 입문과 다른 발견을 재미있는 순간으로 말한다. 길어진 플레이 시간을 난이도 성공의 근거로 삼지 않는다.

실패 시 재설계 순서: 단서 노출·시각 가림 → 조건과 자료 관계 → 조사/첨부 클릭 부담 → 후보 조합과 난이도 순서다. 모두 순회하고 반려 문구만 따라 고르는 행동이 많으면 조사와 판정의 관계를 수정한다. 보상 효과만 늘려 해결했다고 기록하지 않는다.

### 구현 완료 기준

- 입문·중간·도전 모두 시작·조사·선정·근거·검토·반려 수정·완료까지 플레이 가능.
- 진행에 따른 단계 변화와 연습/재개/완료 중복 구분이 일관됨.
- 세 조건과 각 환경·근거 관계가 화면에서 보이고 자체 판정과 일치.
- 지원 기기·입력에서 필수 단서와 행동에 접근 가능.
- 새로고침·탭 전환·후보 변경 후 초안과 관찰 보존.
- 주요 오판정·진행 소실·가독성·직관성 문제를 해결.
- 위 사용자 재미 체험의 실제 결과와 보완을 기록하고 기준을 대조.
- 결과 형식과 연결 조건을 문서화. 본편 연결·배포 여부를 별도로 표시.

입문 구현의 실제 검사와 화면 증거는 [구현 검증](구현검증/검증기록.md)에 기록한다. 위 전체 난이도·실기기·사용자 재미 기준은 아직 모두 완료한 것이 아니다.
