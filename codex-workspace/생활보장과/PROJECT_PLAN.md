# 공문 퍼즐 세 가지 규칙 구현 통합 계획

홍보물 제작 상황과 실제 공문 콘셉트를 바탕으로 A 견본 식별, B 제작계획 추론, C 지시 결과 관찰을 모두 구현한다. 각 규칙을 하나씩 구체화하고 독립적으로 검증한 뒤, 세 규칙을 함께 체험할 수 있는 공문 파트로 통합한다. 최우선 목표는 사용자가 관찰·발견·추리·실험 과정에서 재미를 느끼는 것이다.

## 목표

| 구현 대상 | 플레이어가 할 핵심 판단 | 구현 결과의 기준 |
| --- | --- | --- |
| A 견본 식별 | 관찰한 특징과 사용 조건을 비교해 적합한 제작안을 식별 | 조사·조작·선택·판정·수정이 가능한 퍼즐 |
| B 제작계획 추론 | 흩어진 자료를 연결해 공문에 쓸 계획과 근거를 도출 | 자료 사이의 추론과 공문 작성이 연결되는 퍼즐 |
| C 지시 결과 관찰 | 공문대로 발생할 행동을 판단하고 실행 결과를 보고 지시를 수정 | 작성·실험·관찰·수정·판정이 가능한 퍼즐 |

세 규칙 각각에 판단할 문제, 직접 하는 행동, 이해할 수 있는 결과와 완료 조건을 둔다. C에도 독립적인 판단과 해결 과정이 있어야 한다. 세 규칙이 공문 내용과 업무 결과에 기여하는 연결은 통합 단계에서 검증한다.

## 진행

### 전체 작업 순서

후보별 세부 설계와 구현을 A → B → C 순서로 진행하는 안을 제안한다. A의 관찰·식별 조작을 먼저 검증하고, B에서 자료 관계와 근거를 다루며, C에서 공문에 따른 업무 행동을 다룬다. 실제 플레이 순서와 화면 구성은 후보별 설계 후 정한다.

| 단계 | 할 일 | 산출물과 다음 단계로 넘어가는 조건 | 현재 상태 |
| --- | --- | --- | --- |
| 0 통합 계획 | 세 규칙 전체 구현의 목표·범위·작업 순서 정리 | 이 통합 계획 | 완료 |
| 1 A 세부 설계 | 첫 문제·진행 난이도·상태·화면·자료·판정·저장·결과·검증 계획 | [A 구현 준비 계획](design/공문A_견본식별/A_구현준비계획.md)과 전체 명세·시안 | 작성 완료 · 실제 치수·재미 미검증 |

| 4 B 구현과 검증 | B 한 문제의 시작부터 완료까지 구현하고 체험 | 독립 실행 가능한 B 퍼즐, 추론·근거·재미 검증 결과. 발견한 문제 보완 | 대기 |
| 5 C 세부 설계 | 공문이 유발하는 행동, 공개 규칙, 관찰·수정·완료 조건 결정 | C 상세 설계와 플레이 사례, 필요한 시안. 사용자와 세부사항 확인 | 대기 |
| 6 C 구현과 검증 | C 한 문제의 시작부터 완료까지 구현하고 체험 | 독립 실행 가능한 C 퍼즐, 원인·결과·수정·재미 검증 결과. 발견한 문제 보완 | 대기 |
| 7 공문 파트 통합 | 세 규칙의 결과와 공문 내용을 연결하고 전환·수정·진행 보존 정리 | A·B·C를 모두 체험하는 통합판. 각 규칙의 기여와 상태 일관성 확인 | 대기 |

각 후보는 세부 설계 → 최소 플레이 구현 → 기능과 재미 확인 → 보완 순서로 진행한다. 다음 후보로 넘어가는 시점에는 해당 후보의 핵심 판단이 체험 가능한지 확인한다. 세 후보를 구체화하기 전에 범용 퍼즐 엔진이나 전체 화면을 먼저 완성하지 않는다.

### 후보별 세부 설계에서 정할 사항

| 공통으로 정할 사항 | A에서 정할 사항 | B에서 정할 사항 | C에서 정할 사항 |
| --- | --- | --- | --- |
| 첫 문제의 목표와 플레이 사례 | 어떤 견본을 어떤 상황에서 사용하는가 | 어떤 계획을 어떤 기록으로 알아내는가 | 어떤 지시로 어떤 업무를 움직이는가 |
| 단서와 공개 정보 | 관찰로 드러나는 차이와 결정적인 특징 | 자료 간 연결과 각 자료가 제공하는 부분 정보 | 상대의 능력·행동 조건과 미리 알 수 있는 규칙 |
| 조작과 결과 | 펼치기·접기·시험 등 필요한 행동의 채택 여부 | 자료 조사·근거 연결·작성 방식 | 작성·실험·진행 관찰·수정 방식 |
| 판정과 수정 | 허용 제작안과 부적합 사유 | 허용 결론·근거와 모순 | 허용 계획과 대기·실패·성공의 이유 |
| 난이도와 도움 | 후보 수·관찰 부담·힌트 | 자료 수·읽기 부담·추론 깊이·힌트 | 행동 수·결과 해석 부담·힌트 |
| 화면과 완료 경험 | 비교 방식과 식별 완료의 반응 | 추론을 기억하는 방식과 완성 공문 | 업무 변화와 수정 결과의 표현 |
| 체험 검증 | 사용자가 결정적인 차이를 발견하는가 | 사용자가 자료의 연결을 설명하는가 | 사용자가 지시와 결과의 관계를 설명하는가 |

각 규칙의 상세 기획에는 반드시 참고 게임 반영 항목을 포함한다. 참고작의 실제 구현 방식과 UI를 출처·이미지로 설명하고, 이번 규칙에서 가져올 원리·구체적인 조작·UI 표현·자체 판정·확인할 효과를 대응시킨다. 참고작의 화면·에셋·퍼즐 로직을 복제하지 않고, 참고한 원리가 새 플레이에서 어떤 역할을 하는지 검증한다.

앞선 비교 사례의 견본 수, 특정 장소·담당자, 문구, 조작과 판정은 후보를 설명하기 위한 예시다. 이번 통합 계획에서 세부 명세로 확정하지 않는다.

### 통합 단계에서 연결할 결과

| 규칙 | 다른 규칙과 공문에 전달할 의미 | 연결 검증 |
| --- | --- | --- |
| A | 선택한 제작안과 사용 조건을 충족하는 근거 | 공문의 제작 내용과 실제 선택이 일치 |
| B | 도출한 제작계획과 그 근거 | 공문의 주장과 참고자료의 관계가 유지 |
| C | 작성한 지시와 관찰한 업무 결과 | A·B에서 정한 내용이 실제 행동에 반영 |

각 결과의 정확한 항목과 형식은 해당 후보의 상세 설계에서 정한다. 통합 시에는 앞선 선택을 바꿨을 때 영향을 받는 내용이 무엇인지 알 수 있어야 하고, 해당 부분을 수정할 수 있어야 한다. 초안 보존, 다시 확인할 범위와 완료 상태의 처리 방식도 통합 설계에서 정한다.

공통으로 필요한 문서 표시, 자료 선택, 초안 보존 같은 기반은 새 공문 파트 안에서 공유할 수 있다. 각 규칙의 조사·추론·행동 판정은 개별로 설계한다. 신규 기반의 범위는 실제로 확인된 공통 요구에 맞춘다.

## 결정

### 사용자 요청으로 확정한 범위

- A·B·C 세 규칙을 모두 구현 대상으로 삼는다.
- 각 후보의 세부사항은 하나씩 별도 작업에서 정한다.
- 각 규칙별 계획에는 참고 게임의 구현 방식과 UI를 어떻게 반영할지 반드시 포함한다.
- 홍보물 제작 상황과 실제 공문 콘셉트를 유지한다.
- 기존 시안의 화면·조작·규칙·판정은 새 설계 기준에서 제외한다. 기존 파일은 이전 기록으로 보존한다.
- 기존 게임과 기존 E01 시안의 퍼즐 로직을 재활용하지 않는다. 참고작에서는 재미를 만드는 원리를 참고한다.
- 가장 중요한 성공 기준은 사용자가 재미를 느끼는 것이다.
- 현재 작업의 산출물은 A 입문 독립 실행 화면, 시안형 UI, 자동 검증 결과와 비교 페이지다. 중간·도전·B/C·본편 연결은 진행하지 않는다.
- A는 실물 시험 중심, 한 사건의 핵심 발견 2~3개, 책상 중심·공문 중심 시안 비교, 시안 이미지와 플레이 표 활용으로 구체화한다.
- 두 시안을 비교한 뒤 사용자는 공문 중심 UI를 선택했다. 화면의 실제 치수·폰트·세부 규칙은 별도로 확인한다.
- A는 PC·태블릿·휴대폰 모두 지원, 첫 문제 4견본·3조건·2근거, 독립 완성과 후속 연결 명세, 체크리스트·상태표·정적 시안을 포함한다.
- 입문형과 도전형을 모두 구현하며 게임 진행에 따른 난이도 변화를 적용한다. 구체적인 중간 연결 단계와 후보는 전체 명세에 설계했다.

### 제안하거나 후속 작업에서 정할 범위

- 구체화 순서는 A → B → C를 제안한다. 실제 플레이 순서는 별도로 정한다.
- 한 공문 안의 연속 과정으로 연결할지, 같은 제작 상황의 세 모드로 구성할지 등 통합 형태는 세부 규칙과 체험 결과를 보고 정한다. 어느 형태든 세 규칙을 모두 체험할 수 있어야 한다.
- A의 자료·허용 답·판정·힌트·화면·상태·저장·난이도·결과는 전체 명세에 작성했다. 실제 화면 치수와 체험 결과에 따른 조정은 구현에서 확인한다. B·C의 상세 사항은 미정이다.
- A 체험 인원·절차·개발 판단 기준은 구현 준비 계획에 제안했다. 실제 모집·체험 조건과 결과를 기록하며 계획값을 검증 결과로 표현하지 않는다.
- 화면의 시각 디자인과 조작 시안은 후보별 UI·UX 계획에서 정한다. 기존 화면의 비교 이미지와 변경 후 시안 이미지를 함께 제시한다. 이번 A는 사용자의 코딩 금지에 따라 정적 이미지로만 비교하고, 실제 크기·폰트·비율은 추후 구현이 요청된 단계에서 확인한다. 사용자가 선택한 수치는 해당 상세 설계에 기록한다.
- 신규 공문 파트는 독립적으로 검증한다. 본편 연결과 외부 배포의 시점·범위는 별도 작업에서 정한다.

## 검증

### 후보별 검증

| 검증 대상 | 확인할 내용 |
| --- | --- |
| 문제 성립 | 플레이어가 제공된 정보로 답을 설명할 수 있는가. 복수 답을 허용하면 허용 범위가 명확한가 |
| 판단의 존재 | 관찰·관계 추론·결과 예측 중 해당 후보의 핵심 판단이 실제로 필요한가 |
| 조작의 의미 | 행동이 새 정보를 드러내거나 선택과 결과를 바꾸는가 |
| 판정의 공정성 | 숨은 업무 지식 없이 이유를 이해할 수 있는가. 허용 답과 부적합 사례가 구별되는가 |
| 수정 가능성 | 잘못된 부분을 알아보고 다시 시도할 수 있는가 |
| 사용성 | 처음 보는 사람이 목표와 첫 행동을 이해하고 필요한 자료를 다시 찾을 수 있는가 |
| 재미 | 재미있었던 순간을 구체적인 행동과 결과로 설명하는가. 지루하거나 기계적으로 반복한 부분이 드러나는가 |

기능 확인에는 대표 성공 경로, 그럴듯한 오답, 수정 경로와 실제 규칙의 주요 경계를 포함한다. 재미 확인에는 설명 없이 시작한 행동, 막힌 지점, 발견한 순간과 완료 후 반응을 관찰한다. 완료율과 정답률은 보조 자료로 사용한다.

### 통합 완료 조건

- A·B·C 모두 시작부터 완료까지 직접 플레이할 수 있다.
- 세 규칙 각각에 고유한 판단·조작·판정·수정 과정이 있다.
- 세 규칙의 결과가 공문 내용과 업무 결과에 연결되고 서로 모순되지 않는다.

- 사용자 체험에서 확인한 주요 막힘과 지루한 반복을 보완하고, 사전에 정한 재미 검증 기준을 확인한다.
