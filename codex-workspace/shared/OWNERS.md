채팅 역할이 다르다는 이유로 파일의 내용을 다른 부서로 바꾸지 않는다. 실행 중인 개발 예약과 사용자가 이미 지정한 담당 범위가 있으면 이를 우선 확인해 조율한다.

## 기존 파일의 이관

지금은 폴더와 소통 체계를 분리하고 기존 실행 경로를 유지한다. 실행 중인 `docs/episodes/`를 이동하거나 복제해서 두 개의 원본을 만들지 않는다.

실제 이관은 해당 작업이 끝나고 담당 채팅이 빌드 입력, 상대 경로, 테스트, 문서 링크와 보호 목록을 확인한 뒤 수행한다. 이관 결과를 SPEC과 이 표에 반영하고 관련 채팅에 전달한다. 그 전까지는 기존 경로가 원본이다.

## 수정 예약

각 STATUS의 진행 중 파일 목록을 확인한다. 공통 파일 예약이 겹치면 하나의 담당만 수정하고 다른 섹션은 요청을 전달한다. 예약 기록은 자동 잠금 기능이 아니므로 오래된 기록은 담당 상태를 확인해 정리한다.


## 공통 지침의 원본

공통 작업 규칙은 shared/AGENTS.md 한 곳에서 관리한다. 루트 AGENTS.md는 새 세션을 위한 진입점이고, 섹션별 AGENTS.md는 담당 범위와 고유한 예외만 담는다. 공통 규칙을 여러 파일에 복제하지 않는다. 지침의 관리 담당은 확장계획이며 사용자가 요청한 지침 정리는 해당 요청 범위에서 진행한다.


## 문서 기록의 담당

문서별 역할과 경로는 [DOCUMENTS](DOCUMENTS.md)를 기준으로 한다. 각 섹션의 계획, 로그, 미완료 목록과 결정 기록은 해당 섹션이 관리한다. [공통 운영 작업 로그](2._WORK_LOG.md)는 공통 폴더 구성과 지침 변경의 결과만 기록하며, 섹션별 게임 개발 결과는 담당 기록을 링크한다. 사용자가 요청한 문서 정리는 지정된 범위에서 수행하며 기존 구현 상태와 전달 확인 여부는 보존한다.
