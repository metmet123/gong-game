# 공무원키우기 공통 규격과 통합 기준

## 운영 기준

- 각 섹션은 독립 화면과 콘텐츠를 먼저 검증하고 공통 게임 연결은 확장계획 담당이 조율한다.
- 신규 소스, 테스트, 콘텐츠, 조사 자료와 산출물은 담당 폴더 안에 둔다. 기존 경로 예외는 OWNERS에 따른다.
- 섹션 사이에 공유할 항목은 사건 ID, NPC, 퍼즐 입출력, 저장, 보상, 맵과 소품이다. 변경 제안은 영향 파일과 호환 방법을 포함한 전달 기록으로 남긴다.
- 신규 교차 섹션 ID는 주민센터 `resident-center:`, 생활보장과 `life-support:`, 교통행정과 `traffic:` 접두어를 사용한다. 기존 ID는 유지하고 통합 어댑터에서 매핑한다. 민원봉사과는 별도 `civil-service:`로 구분한다.

## 현재 로컬 코드에서 확인한 기준

| 항목 | 현재 위치 또는 값 | 통합 시 유의점 |
| --- | --- | --- |
| 기존 게임 빌드 | 루트 build_game.py | 루트 소스를 읽고 공무원키우기_플레이.html 생성 |
| 기존 게임 저장 | game-app.js의 civil-servant-grow-v1 | 기존 기록을 덮어쓰거나 삭제하지 않음 |
| 주민센터 저장 | 주민센터/src/services/storage.js의 gong-game:resident-center:v1 | 별도 키 유지, 통합 저장으로 이미 연결된 것으로 간주하지 않음 |
| 생활보장과 E01 | docs/episodes/E01_contract.json | 독립 목업 계약, 본편 통합과 구분 |
| 민원봉사과 계획 | docs/chapters/civil_service/ | 교통행정과 구현과 구분 |

위 코드와 계약은 현재 개발 중이므로 작업 시작 시 최신 파일을 다시 확인한다.

## 기존 기획의 위치

공통 아키텍처는 `../docs/08_TECH_ARCHITECTURE_SAVE_ASSETS.md`, 확장 설계는 `../docs/07_DEPARTMENT_EXPANSION_PACKS.md`, 퍼즐과 화면 기준은 `../docs/PUZZLE_FIRST_V1_1.md`, `../docs/PUZZLE_UIUX_V1_2.md`를 참조한다. 기획에 나온 구조가 구현되었다고 전제하지 않는다. 각 섹션에서 사용자가 이후 확정한 방향은 해당 계획과 결정 기록으로 확인한다.

## 통합 검증 조건

기존 저장 보존, 신규 초안 복원, 사건 및 보상의 중복 방지, 부서 이동 후 상태 유지, 모바일 조작과 빌드 재현을 확인한다. 공통 저장 스키마와 실제 부서 전환 API는 최신 소스 확인 후 별도 합의한다. 이 운영 체계 생성으로 게임 통합 또는 배포가 완료된 것은 아니다.
