# 공무원키우기 섹션별 프로젝트 운영

공통 게임의 기존 실행 경로를 유지하면서 섹션별 신규 작업과 소통 기록을 분리한다. 모든 채팅은 같은 프로젝트 루트에 접근하고 담당 폴더를 지침으로 구분한다.

## 담당 채팅과 폴더

| 담당 채팅 | 폴더 | 역할 |
| --- | --- | --- |
| 공무원키우기 확장 계획 | 확장계획/ | 전체 기획, 공통 규격, 통합 일정, 루트 게임 통합 |
| 공무원키우기 확장_주민센터 | 주민센터/ | 전입신고 퍼즐, 모바일 화면, 주민센터 챕터 |
| 공무원키우기 확장_생활보장과 | 생활보장과/ | 공문, 예산, 민원해결과 생활보장과 에피소드 |
| 공무원키우기 확장_교통행정과 | 교통행정과/ | 부서 확장 설계와 교통행정과 작업 |

교통행정과 채팅의 현재 산출물은 민원봉사과 챕터 계획이다. 해당 내용은 민원봉사과로 유지하고, 교통행정과 구현 완료로 간주하지 않는다.

## 현재 자료와 신규 작업

주민센터는 이미 독립 폴더에서 개발 중이다. 생활보장과의 기존 작업은 `docs/episodes/`, 부서 확장 계획은 `docs/chapters/civil_service/`에 있다. 이 경로는 유지하고 담당은 OWNERS에 명시한다. 이후 신규 독립 작업은 각 섹션 폴더에서 시작한다.

`STATUS.md`는 현재 상태와 전달 확인을 위한 소통용 요약이다. 상세 변경과 검증 이력은 담당 작업 로그를 링크한다. 기존 개발 명세와 작업 JSON은 보존하고, 문서별 역할과 기록 위치는 [문서 역할과 담당](DOCUMENTS.md)에서 확인한다. 상태가 어긋나면 실제 파일과 최신 담당 채팅의 검증 결과를 확인하고 동기화한다.

## 작업 순환

최신 공통 문서 확인 → 관련 전달 확인 → 수정 범위 기록 → 구현과 필요한 검증 → 자기 상태 갱신 → 영향받는 섹션에 전달 기록 생성 순서로 진행한다. 공통 변경은 확장계획 담당이 조율한다.


## 새 세션의 공통 지침 적용

공무원키우기 프로젝트에서 새 채팅을 시작하고 작업 대상과 할 일만 요청한다. 프로젝트 루트의 AGENTS가 shared/AGENTS.md를 읽도록 연결하며, 공통 지침은 작업 내용과 경로로 담당을 판단하고 최신 상태를 확인하게 한다. 채팅별 긴 시작 지시문을 반복해서 붙여넣는 절차는 사용하지 않는다.
