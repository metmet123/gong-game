# 공무원키우기 공통 작업 지침

이 파일은 모든 기존 채팅과 새 세션이 함께 사용하는 공통 작업 규칙의 원본이다. 프로젝트 루트의 AGENTS는 이 파일을 읽는 진입점이다. 경로는 별도 설명이 없으면 프로젝트 루트를 기준으로 한다.

## 새 세션과 담당 섹션 판단

첫 요청의 작업 내용, 지정 경로, 작업 디렉터리와 이미 알려진 채팅 역할을 순서대로 확인해 담당을 판단한다. 새 세션에서 제목이나 이전 대화를 알고 있다고 전제하지 않는다.

| 작업 내용 또는 지정 경로 | 담당 폴더 |
| --- | --- |
| 주민센터, 전입신고, 주민센터/ 안의 작업 | 주민센터/ |
| 생활보장과, E01, docs/episodes/ 안의 공문 예산 민원 에피소드 | 생활보장과/ |
| 교통행정과, 교통 업무, docs/chapters/civil_service/의 기존 부서 확장 계획 | 교통행정과/ |
| 전체 확장 기획, 여러 부서의 통합, 루트 게임과 공통 규격 | 확장계획/ |

민원봉사과 자료를 관리하는 채팅의 역할은 교통행정과이지만 자료의 부서명과 내용은 민원봉사과로 유지한다. 일반적인 공문 또는 예산이라는 단어만으로 담당을 확정하지 말고 대상 콘텐츠와 경로를 함께 확인한다.

구체적인 담당과 기존 경로 예외는 shared/OWNERS.md에 따른다. 여러 섹션이 관련되면 요청의 주요 산출물을 담당하는 섹션이 작업하고 교차 변경은 전달한다. 담당이 불분명할 때는 관련 자료를 먼저 읽고, 수정 범위를 결정하는 데 필요한 경우에만 짧게 확인한다.

## 모바일 질문 방식

전역 질문 지침을 따른다. 질문창은 쓰지 않는다. 답이 없으면 추천안을 적용하지 않고 질문을 답변 최하단에 남긴다. 해당 작업은 멈추고 무관한 작업만 계속한다.

## 매 작업 시작

1. 이 파일과 shared/PROJECT.md, shared/SPEC.md, shared/OWNERS.md를 최신 파일에서 읽는다. 이전 대화의 기억만으로 시작하지 않는다.
2. shared/DOCUMENTS.md에서 문서별 역할과 경로를 확인하고 담당 폴더의 AGENTS와 STATUS, 관련 계획 및 작업 목록을 직접 읽는다. 하위 지침의 자동 로드를 전제하지 않는다.
3. 관련 섹션의 STATUS와 shared/handoffs 중 자신 또는 전체가 수신자인 기록을 확인한다. 자기 STATUS의 전달 확인 표와 비교해 미처리 기록을 파악한다.
4. 자기 STATUS에 공통 지침 확인 시각, 진행 중 작업과 수정할 파일을 기록한다. 이 기록은 실제 파일 잠금이 아니므로 같은 파일을 수정할 다른 작업이 있는지 확인한다.

## 작업 범위와 기존 파일 보존

- 신규 섹션 소스, 테스트, 조사 자료와 산출물은 담당 폴더 안에 만든다. 현재 실행 중인 기존 경로는 OWNERS의 이행 규칙을 따른다.
- 다른 섹션의 코드, STATUS와 기존 원본을 임의 수정하거나 이동하지 않는다. 필요한 교차 변경은 전달 기록으로 요청한다. 사용자가 이미 지정한 변경 범위와 확정된 권한 안의 작업은 추가 승인 없이 진행한다.
- 루트 게임 파일과 공통 규격은 확장계획 담당이 통합한다. 공통 파일을 여러 채팅이 동시에 수정하지 않는다.
- 진행 중인 파일을 이동하거나 두 개의 원본으로 복제하지 않는다. 실제 이관 시 빌드 입력, 상대 경로, 테스트, 문서 링크와 보호 목록을 확인하고 OWNERS와 SPEC을 갱신한다.
- 로컬 구현, 기획 문서와 외부 배포본의 상태를 구분한다. 폴더 생성이나 지침 변경을 게임 구현 또는 통합 완료로 표현하지 않는다.

## 작업 마무리와 변경 전달

- 완료 또는 방향 변경 시 실제 변경과 검증 결과는 담당 작업 로그에 기록하고, 자기 STATUS에는 현재 상태, 필요한 결과 링크와 다음 작업만 갱신한다. 진행 중으로 남긴 수정 예약을 해제한다.
- 기존 상세 진행 문서와 작업 JSON은 역할에 따라 계속 사용한다. 문서 관리와 결과 기록의 위치는 아래 문서 역할 절차와 shared/DOCUMENTS.md를 따른다. 직접 실행한 검사만 자기 검증 결과로 적고, 다른 채팅의 보고는 출처와 확인 시각을 표시한다.
- 다른 섹션에 영향을 주는 변경은 shared/HANDOFF_TEMPLATE.md로 shared/handoffs/YYYYMMDD-HHMMSS-발신-수신-주제.md에 새 기록을 만든다. 제안과 적용된 변경을 구분하고 관련 파일, 영향, 필요한 조치와 완료 조건을 적는다.
- 수신자는 원본 전달 기록을 덮어쓰지 않고 자기 STATUS에 확인, 반영 또는 보류 사유를 기록한다. 답변이 필요하면 새 전달 기록을 만든다.
- 공통 규칙을 고칠 때는 이 파일을 수정한다. 섹션별 AGENTS에는 담당 범위와 그 섹션에만 필요한 예외만 남긴다.

## 프로젝트 문서 역할

문서 관리 방식은 사용자 전역 지침을 따른다. 이 프로젝트에서는 shared/DOCUMENTS.md로 기존 문서의 역할, 경로와 담당만 연결한다. 전역 규칙을 여러 지침에 복제하지 않는다.

- 같은 역할의 기존 문서가 있으면 이름과 위치를 유지한다. 문서가 실제로 있거나 현재 작업에서 생성하기로 한 경우에만 갱신하며, 표준 파일명을 맞추기 위한 중복 문서를 만들지 않는다.
- 섹션별 계획, 로그, 미완료 목록과 결정 기록은 해당 담당이 관리한다. 공통 운영 문서는 확장계획 담당이 관리한다. 공통 운영 로그에 모든 섹션의 게임 개발 이력을 모으지 않는다.
- STATUS는 현재 상태, 진행 중인 수정 범위, 다음 작업, 관련 문서 링크와 전달 확인만 유지한다. 상세 완료 이력과 검증 결과는 담당 작업 로그를 링크한다.
- handoffs에는 다른 섹션에 필요한 변경, 영향과 조치만 기록하고 상세 작업 로그와 검증 근거는 링크한다. 이미 전달된 기록은 보존한다.
- 확정된 구현 명세, 승인된 시안 수치, 검증 기준과 설계 결정은 보존한다. 명세와 실행 계획이 섞인 기존 문서는 전체를 완료 요약으로 줄이지 말고, 명세를 보존한 상태에서 실행 경과만 정리한다.
- TODO의 완료 항목을 정리하더라도 작업 JSON의 완료 상태, ID, 의존성 및 검증 근거는 삭제하지 않는다. 미완료 목록과 기계가 사용하는 전체 작업 그래프를 구분한다.

완료 정리는 실제 결과를 담당 로그에 기록한 뒤 해당 활성 계획을 전역 지침의 완료 요약으로 정리하고, 존재하는 TODO에서 완료 항목을 제거한 후 STATUS와 필요한 전달 기록을 갱신하는 순서로 한다. 기존 상세 설계와 이전 검증 증거는 그대로 보존한다.

파일 저장은 다른 채팅을 자동으로 깨우는 알림 기능이 아니다. 각 세션은 다음 작업 시작 때 최신 상태를 읽는다. 다른 채팅에 메시지를 보낼 때는 사용자가 해당 채팅에 메시지를 보내도록 허용했는지 확인한다.
