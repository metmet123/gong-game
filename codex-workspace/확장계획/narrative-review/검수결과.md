# 스토리·대본 한국어 재검수

최신 후보는 사용자 승인 1B·2A·3B에 따른 [캐릭터·대사·도감 설정 확장본](character-expansion/설정확장결과.md)이다. 12명 관계 장면 36개를 각 6줄로 확장하고 출퇴근 대화와 재방문 맥락을 추가했다. 아래 표현·맥락 검수의 수치는 각 작업 완료 당시 기록이며 현재 확장 검증은 `character-expansion/validation.json`을 따른다.

최신 결과: 비대사 문구의 맥락 검수를 추가 완료했다. 1차 완료본 대비 137개 필드를 더 수정했으며 최초 원본 대비 누적 459개 필드가 바뀌었다. [신문·도감 등 맥락 검수 상세](context-review/맥락검수결과.md)를 따른다. 현재 [확인용 게임](candidate/index.html)과 검증 JSON은 2차 완료본이다. 공개 사이트는 변경하지 않았다.

아래는 1차 표현 검수 당시의 범위·대표 예시다. 후속 맥락 검수에서 신문 규칙 연결·짧은 화면 문구·원본/사본 안내·소품 이력·업적 설명 등을 추가 수정했다. 1차의 ‘quote 외 모두 동일’ 설명은 1차 시점에만 해당하며 최신 후보 변경 범위는 `context-review/html-patches.json`을 따른다.

## 1차 표현 검수 기록

2026-10-11 완료. 대본 데이터의 한국어 문구 859개를 읽고 377개 필드를 수정했다. 같은 문장이 여러 위치에서 쓰이면 각 필드에 반영했다. 377개는 서로 다른 문장 수가 아니라 실제 수정한 데이터 필드 수다.

15일 소식지와 출퇴근 대화, 12명의 인물 프로필·업무 반응·관계 일화, 민원인 8회 방문, 다음 날 업무 결과 21쌍, 부서 회신, 소품·업무·사건 도감, 업적, 엔딩과 다음 분기 대사가 대상이다. 인물마다 말투를 유지하면서 불분명한 비유를 실제 상황과 행동으로 바꿨다. 단비의 파일명 농담처럼 맥락이 분명한 유머는 살렸다.

## 수정 파일과 확인용 게임

- 대본 원본: [narrative_data.json](../../docs/narrative/narrative_data.json)
- 사람이 읽는 대본: [narrative_concept.md](../../docs/narrative/narrative_concept.md)
- 수정 전후 전체 목록: [changes.json](changes.json)
- 수정 대본을 적용한 게임: [candidate/index.html](candidate/index.html)
- 검증 결과: [validation.json](validation.json), [runtime-validation.json](runtime-validation.json)

확인용 게임은 GitHub 본편 `index.html`의 blob `46a89e50e3bc67d19db80ea7b154c9013afb7150`을 읽어 별도 파일로 만들었다. 내장 Narrative 데이터가 로컬 수정 전 원본과 같음을 확인한 뒤 새 대본을 넣었다. 원격 파일은 수정하지 않았다.

사무실 말풍선은 프로필과 별도로 옛 `quote`를 읽고 있었다. 확인용 게임의 대본 연결 한 곳에 `quote:c.profile.habit`를 추가해 수정한 말버릇이 실제 말풍선에도 적용되게 했다. 나머지 코드·화면·저장·보상·퍼즐 판정은 배포본 사본과 동일하다.

## 검증과 남은 확인

JSON 구조·ID·발화자·등장일·해금·조건·제안 필드 보존, 대본 문서와 데이터의 일치, 민원인 프로필 중복 위치와 소품 설명의 일치, 보조 완료 시 같은 업무 결과 유지, 내장 스크립트 6개 문법 검사를 통과했다. 실제 Week 모듈을 실행해 15일 소식과 한마디, NPC 말버릇·완료 반응에 새 대본이 연결됨을 확인했다.

표시 문구의 최대 길이는 공백·문장부호 포함 67자다. 길이는 측정값이며 모바일 화면 검수 통과를 뜻하지 않는다. 실제 모바일 줄바꿈, 전체 게임 플레이 및 공개 사이트 반영은 미실시다.

재현 명령: `python 확장계획/narrative-review/validate.py`, `node 확장계획/narrative-review/check-runtime.cjs`. `revise.py`는 보관된 수정 전 대본을 기준으로 검수본을 다시 생성하므로, 이후 대본이 바뀐 뒤에는 그대로 실행하지 말고 변경 사항을 먼저 합쳐야 한다.
