# 퍼즐 앱 참고 디자인과 직관적 조작 계약 v1.2

2026-10-11. **사용자 확정 [U]**: 각 퍼즐에 시중 프로그램/앱의 작업 화면을 참고한 세련된 디자인, 직관적인 진행 방식. **디자인 제안 [D]**: 아래 앱 선정·화면 구성·조작 흐름·색상. **구현 사실 [I]**: 이번 변경은 문서와 시안에 반영했다. 신규 판정기와 모바일 실기 테스트는 아직 없다. 퍼즐 먼저 구현하는 PF0~PF6·TASK39개는 유지한다.

## 공통 화면과 진행 흐름

1. 상단에 한 문장 목표와 필수 조건을 둔다. 처음에는 해야 할 조작 한 가지를 구체적으로 제시한다.
2. 자료 → 작업 → 확인의 진행 위치를 보여준다. 자료/규칙은 쉽게 다시 열고 초안을 유지한다.
3. 선택한 카드·칸·블록은 테두리와 선택 글자로 표시한다. 선택 후 가능한 행동만 가까이 보여준다.
4. 하단에는 확인하기 하나를 주 행동으로 둔다. 되돌리기·힌트·처음부터는 보조 행동이다. 확인과 최종 제출을 구분한다.
5. 확인은 보상을 주지 않는다. 미완료/위반은 작업을 유지하며 ‘무엇이 잘못됐는지 → 해당 위치 → 수정 방법’을 보여준다. 유효한 평가에만 제출을 제공한다. 평가 후 수정하면 제출 가능 상태를 해제하고 다시 확인한다.
6. 제출 성공은 기존 판정·보상 계약으로 처리한다. 여러 유효 해법을 허용하고 성공 연출·일화가 작업을 막지 않는다.

처음 1문제는 목표→첫 선택→변화→확인의 짧은 안내를 제공하고 이후 접어둔다. AND/OR는 ‘모두 충족/둘 중 하나’, trace는 ‘실행 기록’, VM은 ‘처리 실행’으로 표기한다. 자료 속 ID는 내부 데이터로 유지하되 플레이어에게 가상의 문서명·목적·금액을 보여준다.

## 스타일과 모바일 계약

- 화면은 밝은 중성 배경·흰 작업 패널·짙은 잉크색 글자·한 가지 강조색을 기본으로 한다. 8px 간격 단위, 패널 12px 안팎 모서리, 일정한 1px 테두리, 과하지 않은 그림자를 사용한다.
- 의미 없는 장식과 메뉴를 늘리지 않는다. 본문은 게임 구현 시 최소 14px, 중요한 조작은 44×44 CSS px 이상. 시안집의 3열 축소 그림은 조작 크기 시험 대상이 아니다.
- 선택=파랑+테두리, 성공=초록+체크, 오류=진한 빨강+이유, 잠금=자물쇠+잠금 문구. 색만으로 뜻을 전달하지 않는다.
- 카드·타임라인·격자는 유형별로 다른 작업면을 사용하고 상단 목표·하단 확인·undo 위치만 공유한다. 픽셀 그림은 아이콘·물품·NPC·도장에 쓰며 긴 본문은 일반 UI 글꼴로 읽힌다.
- PC는 자료/작업/결과를 나란히, 휴대폰은 자료/작업/확인 패널을 전환한다. 현재 선택·초안·목표 요약은 전환해도 유지한다. 12개월 예산은 분기 탭과 연간 요약을 함께 표시한다.
- 드래그는 선택 기능이다. 부품→칸→방향, 사업→시작 월→행, 문서→날짜, 단계→위/아래 버튼으로 모든 핵심 작업을 끝낼 수 있어야 한다. 서고는 상자를 자유 배치하지 않고 방향 버튼으로 이동/밀기만 한다.
- 모바일 조작 바는 화면 하단에 고정하되 safe-area와 키보드를 고려한다. 격자·표는 내부 스크롤/확대를 제공하고 페이지 전체 가로 넘침을 피한다. 7열 보드가 320px에서 작아지면 확대와 칸 선택 보조를 제공한다.
- 이 시안집의 모든 그림·목차·출처·설명은 JavaScript 없이 읽을 수 있다. 시안 버튼은 실행 버튼이 아니다. 실제 게임에는 JavaScript가 필요하다.

## 유형별 오류와 완료 조건

### 규정 개정

금액 100 이상 → 과장 분기는 잠겨 있습니다.

- 오류: B 현장 신청이 거절됨 · 접수 조건으로 돌아가기
- 완료: 4건 모두 기대 결과와 같음
- 연결 TASK: PF1-RUL / PF2-RUL

### 서류 주인 찾기

단서와 배정표를 동시에 확인하며 추리합니다.

- 오류: 파랑 서류가 두 사람에게 배정됨 · 해당 배정 수정
- 완료: 중복 없이 모든 단서 충족
- 연결 TASK: PF1-OWN / PF2-OWN

### 결재 동선

출장·선행·마감은 날짜 옆 표식으로 표시합니다.

- 오류: 과장이 계장과 같은 날임 · 화요일 이후로 변경
- 완료: 선행·용량·마감을 모두 지킴
- 연결 TASK: PF1-APR / PF2-APR

### 한 장 보고

필수 사실과 분량을 문서 바로 아래에서 확인합니다.

- 오류: 예산 사실이 빠짐 · 예산 카드를 보고서에 추가
- 완료: 필수 사실 3개 보존 · 분량 4칸 이하
- 연결 TASK: PF1-BRF / PF2-BRF

### 매크로 설계·디버깅

실행 중인 블록과 입력·출력을 같은 색과 번호로 연결합니다.

- 오류: 중복 A가 두 번 합산됨 · 중복 제거 블록 확인
- 완료: 공개·경계값 테스트 모두 통과
- 연결 TASK: PF1-MAC / PF2-MAC

### 서고 정리

평면도 표현을 참고하며 실제 규칙은 밀기만 허용합니다.

- 오류: 상자를 밀면 코너에 갇힘 · 한 수 되돌리기
- 완료: 모든 상자의 연도와 목표 칸 일치
- 연결 TASK: PF1-ARC / PF2-ARC

### 예산 테트리스

A는 가로 2개월×세로 1단위이며 회전할 수 없습니다.

- 오류: 1분기 한도 3을 초과함 · 사업의 시작 월 수정
- 완료: 사업 모두 배치 · 월·분기 한도 충족
- 연결 TASK: PF1-BUD / PF2-BUD

### 결재 컨베이어

모바일은 부품→칸→방향으로 배치하고 드래그를 요구하지 않습니다.

- 오류: 승인 A에 계장 도장이 없음 · 문제 경로로 이동
- 완료: 모든 원본이 필요한 도장·수량·목적함 충족
- 연결 TASK: PF1-CNV / PF2-CNV

### 서류 대조

모바일에서도 같은 항목의 원본/제출값을 한 줄에 놓습니다.

- 오류: 기간까지 오류로 표시함 · 선택 항목 재검토
- 완료: 오류 항목 집합이 원본 규칙과 정확히 같음
- 연결 TASK: PF2-LEG

### 자료 취합

승인 상태와 버전을 파일명보다 크게 표시합니다.

- 오류: 예산 v3는 미승인 · 승인 자료 중 최신 버전 선택
- 완료: 각 분류에서 최신 승인 자료 한 개씩 선택
- 연결 TASK: PF2-LEG

### 전화 메모

다시 보기와 메모를 허용하며 통화 종료 후에도 초안을 유지합니다.

- 오류: 회신 시각이 다름 · 통화 다시 보기
- 완료: 문제의 핵심 항목이 모두 일치
- 연결 TASK: PF2-LEG

### 처리 순서

매크로보다 단순한 순서 편집으로 자동화에 익숙해집니다.

- 오류: 필터 전에 합산함 · 합산 카드를 뒤로 이동
- 완료: 기존 두 입력 테스트를 모두 통과
- 연결 TASK: PF2-LEG

### 부서 안내

위험 우선 규칙을 요청 카드 바로 아래에 항상 보여줍니다.

- 오류: 위험 신호를 놓침 · 안전 우선 규칙 확인
- 완료: 안전 우선 규칙을 포함한 기존 분류 판정 충족
- 연결 TASK: PF2-LEG

### 재활용 선별장

통별 용량과 물품 기호를 늘 표시합니다.

- 오류: 다른 종류 위에 놓을 수 없음 · 다른 통 선택
- 완료: 모든 물품이 동종 묶음으로 정리됨
- 연결 TASK: PF6-01

### 상수도관 연결

연속 드래그와 칸 탭을 모두 지원합니다.

- 오류: 보호칸을 통과함 · 해당 구간 되돌리기
- 완료: 모든 쌍 연결 · 교차·보호칸 위반 없음
- 연결 TASK: 후속 개별 TASK

### 불법주차 견인

차를 끌지 않고 탭 한 번으로 지정 방향 출차를 요청합니다.

- 오류: A 앞에 B가 있음 · 막는 차량 표시
- 완료: 소방로 우선 조건과 전 차량 출차 충족
- 연결 TASK: 후속 개별 TASK

### 지적도 복원

칠하기/제외/지우기 모드를 분리하고 길게 누르기를 필수로 하지 않습니다.

- 오류: 2행의 연속 칸 수가 3이 아님 · 해당 줄 확인
- 완료: 모든 행·열 run 힌트 일치
- 연결 TASK: 후속 개별 TASK

### 기록물 철하기

## 단계별 구현에 붙일 완료 기준

PF0-02 공통 계약에 selection, draftRevision, evaluationRevision, firstAction, errorTarget을 둔다. 필드 이름은 제안이며 판정은 기존 규칙을 따른다. UI 레이어와 판정기를 분리하고 현재 초안 revision과 같은 유효 평가에만 제출을 허용한다.

PF1의 각 게임 TASK: 목표·첫 조작·현재 선택·확인·되돌리기를 러프 UI에서도 보여준다. 탭/클릭만으로 대표 문제를 풀고, 틀렸을 때 작업을 지우지 않아야 한다. PF1-GATE에서 8종의 이 흐름을 직접 확인한다.

PF2의 각 게임 TASK와 PF2-LEG: 타입별 작업면·선택 도구·오류 위치·모바일 대체 조작을 구현한다. PF2-GATE에서 정답/오답/미완료/확인 후 편집/중단복원/확인과 제출 구분을 시험한다. PF5 전까지 실제 신규 엔진과 시안집 점검을 분리한다.

직관성은 화면 검사만으로 통과했다고 쓰지 않는다. PF2-GATE의 사용자 시험 제안: 처음 보는 사람 5명이 유형별 첫 문제를 플레이한다. 각 유형에서 4/5 이상이 구두 도움 없이 10초 내 첫 조작을 고르고, 60초 내 오답 이유를 찾아 수정하는 것을 목표로 한다. 풀이 완료 시간과 혼동 원인을 기록하고 실패한 흐름만 개선한다. 이는 게임 제작 중 확인할 목표이며 현재 결과가 아니다.

PF5-02: 320/360/390/412px, 큰 글씨, 키보드, 무음/동작 줄이기를 점검한다. 글자 대비·터치 목표·하단 바 가림·격자 선택 정확성은 실제 게임 빌드에서 확인한다. Android/Samsung 파일 뷰어와 실제 브라우저의 결과를 따로 기록한다.

PF6의 11종은 후속 후보다. 이번에는 디자인과 흐름을 정리하고 샘플팩 1개 우선 계획을 유지한다.
