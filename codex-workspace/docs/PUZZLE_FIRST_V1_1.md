# 3단계 화면 시안과 퍼즐 우선 구현 계획

계획 v1.1 · 2026-10-11. 사용자가 확정한 변경은 **화면을 3단계로 먼저 비교하고, 퍼즐을 독립적으로 플레이 가능하게 만든 뒤 사무실·성장·스토리를 연결하는 순서**다. 개별 그림·모듈 구현 순서·콘텐츠 수량은 아래 권장안이다. 이번 산출물은 시안과 실행 계획이며 게임 구현 TASK는 모두 planned다.

> **시각·조작 계약 v1.2 적용**: `PUZZLE_UIUX_V1_2.md`와 `data/puzzle_uiux_v1_2.json`의 앱 참고, 첫 조작, 유형별 작업면, 확인/제출 구분, 모바일 대체 조작을 따른다. PF0~PF6 순서와 TASK39개는 유지하고 아래 인수 기준을 보강했다. 사용자 확정은 세련된 앱 참고 디자인과 직관적인 진행 방식이며 개별 앱·구성·시험 수치는 제안이다.

## 적용 우선순위

구현 순서는 이 문서와 `tasks_puzzle_first_v1_1.json`의 PF0~PF6을 따른다. 기존 `09_PHASED_ROADMAP_AND_TASK_BACKLOG.md`, `12_NEXT_IMPLEMENTATION_HANDOFF.md`, `tasks.json`의 P0~P11 순서와 선행 관계는 v1.0의 이전 계획이다. 기존 TASK의 기술 계약·시험 항목은 참고하되 새 PF 의존성과 혼합하지 않는다. 게임 규칙·원본 배치·경제·스토리 ID는 기존 02~08과 `planning_contract.json`을 재사용한다.

**새로 확정 [U]**: 3단계 비교 시안, 퍼즐 먼저 구현. **이번 제안 [D]**: rules→owner→approval→brief→macro→archive→budget→conveyor 순서, PF 마일스톤과 단계별 문항 수. **구현 사실 [I]**: 기존 5종 규칙과 기준 게임은 이미 존재하며, 신규 8종 엔진·새 이동/카메라는 아직 없다. **후속 후보 [A/D]**: 타과11종은 생활보장과 베타 이후 개별 선택한다.

## 시안의 3단계

|단계|목적|꼭 보여줄 것|다음 단계로 넘어가는 기준|
|---|---|---|---|
|01 구조 러프|정보 배치와 조작 순서 확인|큰 목표·규칙·편집 영역·검증·제출·뒤로가기|첫 조작이 명확하고 규칙을 그림 없이 이해할 수 있음|
|02 기본 플레이형|실제로 풀 수 있는 조작과 판정|선택→편집→검증→제출→재시도, undo·힌트·오류 이유·초안 복원|신규8종에서 정답/오답/미완료를 구분하고 조건이 같은 복수해를 수용|
|03 디테일 목표형|손맛·장소 분위기·보상 연결|픽셀 자산·짧은 도장/이동·NPC·소품·소리·구역 복귀|02와 판정·터치 조작이 같고 연출 중 중단/복원에도 진행·보상이 안전|

이 단계는 **완성도**이며 난이도 하/중/상과 다르다. 같은 대표 문제를 세 단계에 사용한다. 03 그림은 목표 시안이고 최종 픽셀 자산 제작 완료를 뜻하지 않는다. 시안 속 편집/실행 버튼 그림은 게임 판정기를 실행하지 않는다. 문서 목차·검색·원문 풀이 펼치기만 문서 기능이다.

범위: 신규8종·기존5종 각각3장=39장, 전체 지도+7구역+공통11화면 각각3장=57장, 후속 타과11종 각각3장=33장. 총 **43개 항목·129개 화면 시안**. 대표는 모바일 세로 화면이며 PC에서는 같은 판정과 탭 조작을 유지하고 자료와 편집을 나란히 배치한다. Android 실제 기기는 미검증이다.

PF0의 원본 보호와 공통 퍼즐 계약은 먼저 필요하다. **사무실 BFS·카메라·NPC·경제·전체 캠페인 저장을 신규 퍼즐 플레이의 선행 조건으로 두지 않는다.** PF1 초안은 단순 JSON으로 내보내거나 전용 임시 키에 저장하고, 원본 저장은 읽거나 쓰지 않는다. PF2의 전용 퍼즐 저장은 PF3의 캠페인 저장 어댑터와 분리한다. PF1 UI가 회색이어도 플레이 완료로 인정할 수 있지만, 판정·취소·다시 시도가 실제로 동작해야 한다.

PF1은 각유형의 가장 작은 문제부터 시작한다. PF2에서 조건/복사·경계값·연도·일정용량·분기·보고서 결합을 확장해 기존 대표24문제를 구현한다. PF4에서 각난도3개=유형당9개/총72개로 늘린다. PF1 8개와 PF2 24개는 PF4 72개에 포함하며 합산해104개라고 부풀리지 않는다. 하/중/상은 제작 난도가 아닌 플레이 난도다.

PF TASK는 상대 규모 기준이다. 날짜나 소요시간을 확정하지 않는다. 한 모듈은 판정 → 최소 UI → 유효 해법 → 실패 이유 → 중단·복원 → 체험 빌드 순으로 진행하고, 위 완료 증거가 있어야 done으로 바꾼다. 상위 게이트가 실패하면 다음 단계의 장식과 콘텐츠 양을 늘리지 않는다.

## 공통 판정과 인수 조건

1. 판정은 DOM·캔버스·지도·벽시계·저장·XP/P에서 독립한 순수 함수다. Stage의 seed·난도·contentVersion은 시작 시 고정한다.
2. 편집 action을 undo/reset으로 복원한다. 검증에서 초안을 지우지 않으며 미완료·위반·엔진오류를 구분한다.
3. 복수해는 결과와 제약으로 판정한다. owner 기본은 유일해를 별도로 증명한다. 픽셀 위치·카드 이름·폰트·다른 행·정렬이 답을 바꾸지 않는다.
4. PF1 최소문제도 실제 편집과 성공/실패가 있어야 한다. 정답 버튼·고정 witness 재생만으로 플레이 완료라고 하지 않는다.
5. PF2부터 무료힌트3·보조완료·중도 초안을 제공한다. 실제 XP15/P20·일차결산15P는 PF4에서 원장과 연결한다.
6. 휴대폰은 drag 없이 선택→칸탭/위아래로 풀 수 있어야 한다. 긴 격자는 내부 확대/이동·날짜/분기 탭으로 처리하고 하단 핵심 조작을 유지한다.
7. PF4 경제 총수입1455P(시작30 포함), 도구690P+소품735P=1425P, 잔여30P를 재검사한다. 기존 도구 가격·해금일·난도별 보상은 변경하지 않는다.
8. 신규 판정기 실행 시험, 24/72개 해존재 검사, 문서 그림 검증, 실제 Android 시험을 서로 다른 증거로 기록한다. 현재 3단계 HTML 검증은 신규 게임 완성 증거가 아니다.
