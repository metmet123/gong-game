# 홍보물 200부 1번과 2번 UI UX 개선 계획

분석 대상은 독립 에피소드 목업 v0.2의1번 사업 편성과2번 공문 작업대다. 우선 UI·UX·직관성을 개선하고, 퍼즐의 예산·제작수량·최신자료 조건은 유지한다. 아래는 원래의 분석과 개선 계획이다. 이후 붙임 시안 네 개의 화면 구성을 참고해 [직접 조작하는 새 시안](E01_묶음1_휴대용시안.html)을 구현했다. 적용 결과는 [디자인 해설](E01_01-02_게임화면_디자인해설.md)과 [기존 화면 비교](E01_묶음1_디자인비교.html)에서 볼 수 있다.

현재 데스크톱·모바일 캡처, 화면 구성과 입력 처리 코드를 확인했다. 실제 사용자 관찰을 수행한 결과는 아니므로 오해와 행동 지연은 검증할 가설로 구분한다.

## 핵심 진단

현재 화면은 차분한 색과 카드·공문 외형이 일관되고, 같은 방식으로 자료를 선택하고 놓을 수 있다는 장점이 있다. 그러나 화면이 설명과 수첩을 따라야 조작 방법을 이해하도록 구성돼 있다. 사용자가 첫 화면에서 현재 상태·첫 행동·행동 결과를 찾기 쉽도록 구조를 바꾼다.

|대상|가장 큰 문제|우선 개선|
|---|---|---|

|1번 예산편성|칩·사업·사건·실행 버튼이 세로로 멀리 떨어짐|칩을 묶음으로 표현하고 사건을 제작 카드 옆에 배치|

## 확인한 화면 수치

브라우저에서1440px와390px 너비로‘주요 화면 둘러보기’의 각 장면 초기 상태를 확인했다. 높이844px에서 모바일1번 페이지는2172px,2번은2027px였다. 둘러보기 안내 배너와 예산 상태에 따라 실제 플레이 화면의 높이는 달라진다.

390px에서 공문의 첫 수정 필드는 페이지 상단 기준983px에 있었으며 자료 트레이는526~774px에 있었다. 필드 높이는35px, 글자는12px였다. 화면 하단의 피드백과 실행 버튼도 첫 화면 바깥에 있었다. 이는 내용이 잘리지는 않는다는 기존 검증과 별개의 문제다. 사용자가 조작과 반응을 같은 시야에서 확인할 수 있는지 다시 확인해야 한다.

관측값은E01_01-02_UIUX_관측.json에 저장했다.

## 1번 사업 편성

### 돈을 읽는 기준

현재‘사업예산260,000원/실제지급0원/남은돈260,000원’과‘제작22칩/거치대2칩/예비2칩’이 동시에 보인다. 지급하지 않은 실제잔액260,000원은 수학적으로 맞지만 편성 중인 사용자에게는 앞으로 더 배치할 수 있는 돈처럼 읽힐 수 있다.

이 장면의 주 요약을‘총26칩/배정24칩/미배정2칩’으로 바꾼다. 원화는2칩(20,000원)처럼 보조 표기로 제공한다. 실제 지급액은 지급 장면에서 주요 지표가 된다. 예비비라는 업무 용어는 미배정 예산의 설명에서 함께 보여준다.

### 화면 크기와 정보 우선순위

제작 카드와 예비 트레이가 동일한 크기라, 남은2칩을 보여주는 영역에도 큰 빈 공간이 생긴다. 제작 카드에는 칩22개가 펼쳐져 모바일에서 높이를 많이 차지한다.

제작을 주 작업 카드로 두고 미배정 예산은 상단의 작은 트레이로 압축한다. 칩은10칩묶음 두 개와 낱개2개로 표현한다. 낱개 이동 조작은 유지하되 숫자를 전달하기 위해 동전22개를 모두 늘어놓지 않는다. 총액·배정·잔여의 관계를 한 줄로 읽게 한다.

상단의 전체8단계 목록과 목업 모드 선택은 작업 시작 전에 차지하는 공간이 크다. 모바일 기본 표시를‘1/8 사업 편성’과 진행 표시로 줄이고 전체 목록은 펼쳐서 보게 한다. 목업의 처음부터 플레이·둘러보기는 접은 체험 메뉴로 옮긴다.

### 첫 조작

현재+10칩/+1칩/−1칩 중 무엇부터 눌러야 할지 수첩에서 알아내야 한다. 처음에는 제작 카드에‘제작비20칩 배정’을 한 번 제공한다. 배치가 끝나면 미배정 예산이6칩으로 바뀌고 칩이 움직인 결과를 가까이 보여준다. 이후의+1/−1은 조정할 때 사용한다.

선택 사업은 카드 전체를 눌러 선택·해제한다. 카드의 상태를‘선택하기/선택됨✓/선택해제’로 표시한다. 필수 제작은‘필수🔒’로 구분한다. 현재의‘사업활성화’와‘칩돌려놓기’보다 사용자의 결정이 직접 드러나는 문구를 사용한다.

각 카드에는 이름·비용·이후 효과를 같은 순서로 배치한다. 효과는 짧은 행동 문장으로 적고, 아직 구현하지 않은 지원 효과는 실제 목업 UI의 기능으로 소개하지 않는다.

### 가격 상승과 다음 행동

현재 견적 변경 안내는 선택 사업 아래에 있어 모바일에서 제작 카드와 함께 보기 어렵다. 제작 카드 옆에‘제작비가20→22칩으로 변경됨/2칩추가필요’를 표시한다.

미배정 예산이2칩이상이면‘2칩옮기기’를 제공한다. 부족하면‘현재미배정1칩/1칩부족’을 보여주고 선택 사업을 해제할 수 있음을 카드 가까이 알린다. 어떤 사업을 해제할지는 플레이어가 고른다.

가능하지 않은 증액 버튼은 비활성화하고‘미배정예산부족’ 또는‘필요금액배정완료’를 근처에 표시한다. 눌러서 오류를 확인해야만 제약을 아는 방식은 줄인다.

### 실행 흐름

필수 배정 → 선택 사업 → 견적 확인 → 필요 시 조정 → 계획 확정이다. 주 실행 버튼은 현재 상태에 맞춰‘견적확인’ 또는‘계획확정’으로 바뀐다. 별도의‘작업확인’버튼 없이, 눌렀을 때 내부에서 최신 상태를 검토하고 오류가 있으면 해당 카드에 이유를 표시한다.

예산 조정은 되돌릴 수 있고, 확정 이후에는 결재 전까지의 수정 정책을 따로 정한다. UI 개선만으로 이미 확정한 거래를 취소하도록 만들지 않는다.

## 2번 공문 작업대

### 문서와 자료의 관계

현재 모바일에서는 자료6장이 먼저 나오고 그 아래에 긴 공문이 있다. 자료를 선택한 뒤 필드를 찾아 내려가야 하므로 무엇을 선택했는지 기억해야 한다. 선택한 자료 표시도 작업면 상단에만 있어 필드와 함께 보이지 않을 수 있다.

기본 행동을‘공문에서 바꿀 칸 누르기 → 관련 자료 선택’으로 바꾼다. 자료를 먼저 보고 가져오는 기존 행동도 보조 방식으로 유지한다. 칸을 누르면 해당 내용을 확대하고 모바일 하단에 관련 자료 선택창을 연다. 현재 값·선택 자료·교체 후 값이 같은 시야에 있어야 한다.

자료창을 열었다고 새 값을 자동 입력하지 않는다. 자료의 값과 출처를 고른 후‘적용’하면 문서와 자료창의 표시가 함께 갱신된다. 취소하면 이전 내용은 유지한다. 키보드에서도 필드버튼 → 자료버튼 → 적용 순서로 이동할 수 있다.

### 조작 가능한 부분

수정 필드의 점선 테두리는 빈칸이나 강조로도 읽힐 수 있고, 자료 없이 필드를 누르면 오류가 나온다. 필드를 누르는 자연스러운 행동에 편집창이 열리게 한다.

수정 필드에 연필 표시 또는‘수정’텍스트를 붙이고 터치 높이는44~48px, 본문과 편집 값은16px안팎으로 확보한다. 큰 공문을 축소한 상태로 편집하지 않고 필요할 때 해당 문단을 확대한다. 기관명·수신·문서번호 등 보조 정보는 작은 글자로 남겨도 되지만 조작에 필요한 숫자는 작게 만들지 않는다.

처음부터 오류 칸을 붉게 칠하면‘편집가능’과‘오류’의 의미가 섞인다. 기본 필드는 중립적인 편집 표시를 사용한다. 사용자가 비교하거나 검토했을 때 문제 메모를 붙이고, 수정 완료는 체크와 출처로 구분한다. 의미를 색만으로 전달하지 않는다.

### 반복 자료와 붙임

현재‘견적v2의1,100원’과‘견적v2붙임’은 서로 다른 카드다. 실제로 같은 견적서를 숫자용과 붙임용으로 두 번 찾게 한다. 견적서 한 장 안에서 단가를 가져오고 그 종이를 붙임에 넣게 한다.

자료는 배부계획·견적서·최신공지·규격견본처럼 실제 서류 단위로 구분한다. 오래된 자료도 같은 종류 안에서 날짜와 사업명으로 식별하게 하되, 첫 편의 필수 자료량을 늘리지 않는다. 공문 전체를 한 번에 내려다보려는 사용자에게는‘전체보기’를 제공한다.

붙임은 공문 아래의 두 종이 클립 슬롯으로 표시한다. ‘견적서/규격견본/붙임1/2’처럼 이름과 진행을 보여주고 빈칸을 누르면 관련 자료를 선택할 수 있다. 본문 수정에서 확인한 견적서도 다시 찾아야 하는 대신 바로 붙임에 넣을 수 있게 한다.

### 오류와 완료

현재 모든 피드백이 작업면 아래에 모인다. 공문이 긴 모바일 화면에서는 수정한 자리와 결과 메시지를 동시에 보기 어렵다.

단가에 문제가 있으면 산출칸에 빨간 메모를 붙인다. 메모를 누르면 관련 견적서를 함께 보여준다. 잘못된 값만 수정하고 다른 정상 내용은 유지한다. 화면 하단에는 짧은 상태‘작성중/검토필요/기안준비완료’를 표시한다.

주 실행 버튼은‘기안완료’하나로 통일한다. 누르면 현재 내용과 붙임을 검사하고, 유효하면 담당 도장을 찍고 다음 장면으로 넘어간다. 문제가 있으면 첫 문제 위치로 이동한다. 현재의‘작업확인 → 서류철묶기→결재’두 버튼이 만들어내는 클릭 순서를 줄인다.

담당·협조·계장·과장 결재란은 공문 외형에 남긴다. 이번 장면에서 찍는 것은 담당 도장임을 설명하고 나머지는 다음 결재 단계의 상태로 표시한다. 사용자가 이 장면에서 네 도장을 모두 채워야 한다고 오해하지 않게 한다.

## 두 장면의 연결

1번에서 확정한 사업·예산·견적을2번에서도 같은 이름·단위·색으로 보여준다. 선택 사업은 간단한 칩 형태 요약이고, 공문을 고치는 동안 항상 필요한 정보만 남긴다.

1번 완료는‘계획확정’,2번 완료는‘기안완료’다. 둘 다 확정될 때만 다음 단계로 진행한다. 전환 메시지는‘확정한 계획으로 공문을 준비했어요’처럼 결과를 설명하고 추가 조작 설명은 첫 문서 칸을 눌렀을 때 보여준다.

먼저P0을1·2번에 적용한 뒤 실제 사용자가 조작을 이해하는지 확인한다. 기존 게임의 로직을 가져오는 구현은 사용하지 않는다. 다른 여섯 장면의 UI·게임 규칙은 이 묶음의 개선 계획에 포함하지 않는다.

## 사용자 확인 항목

첫 사용자5명에게 조작 순서를 설명하지 않고 다음을 확인한다. 아래는 개선 목표이며 아직 확인한 결과가 아니다.

- 첫10초 안에 시작할 행동을 찾는지.
- 편성 화면에서‘지금 추가로 배치할 수 있는 돈은 얼마인가’에 정확히 답하는지.
- 견적 상승 뒤 무엇이 바뀌었고 어떤 조정이 필요한지 말할 수 있는지.
- 공문 필드를 눌렀을 때 설명 없이 자료 선택과 적용을 완료하는지.
- 붙임의 역할과 현재 완료 수를 이해하는지.
- 잘못된 값을 넣은 뒤 오류 위치로 이동해 정상 내용을 유지하며 수정하는지.
- 모바일에서 자료를 기억하기 위해 위아래로 반복 스크롤하는지.

목표는5명중4명이 첫 행동과 필드 적용을 도움 없이 수행하는 것이다. 인원은 초기 문제를 찾기 위한 작은 표본이며 전체 사용자의 이해도를 입증하지 않는다. 기능 테스트에서 페이지 넘침이 없었다는 결과와 사용자의 이해·편의 확인은 별도로 기록한다.
