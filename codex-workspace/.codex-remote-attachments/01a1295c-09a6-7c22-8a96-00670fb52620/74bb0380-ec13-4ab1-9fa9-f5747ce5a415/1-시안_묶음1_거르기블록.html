규칙 (판정 기준)

  • 서류함 3~4칸, 각 칸에 서류가 쌓임(아래→위). 로봇은 레일 위 한 칸에 있고, 처음엔 빈손.
  • 카드: ←/→ 한 칸 이동(끝에서 더 가면 그 자리) · ✋ 빈손이면 맨 위 서류 집기, 들고 있으면 맨 위에 놓기(칸 높이 제한 넘으면 못 놓음) · 1·2·3 그 줄 프로그램 실행(자기 줄을 부르면 반복).
  • 색 딱지: 카드에 🟩/🟥/🟨/‘빈손’/‘들고 있음’ 딱지를 붙이면 조건이 맞을 때만 실행.
  • 프로그램 줄 수(1~3)와 줄마다 칸 수가 레벨마다 정해져 있음 = 난이도의 핵심.
  • 성공: 실행 도중 목표 모습과 같아지는 순간. 실패: 1번 줄이 끝났는데 목표가 아님 / 500단계 넘음(‘로봇이 지쳤어요’).
  • 시험이 여러 개인 레벨(상 11~): 서류 수가 다른 시작 모습 2~3개를 차례로 돌려 모두 성공해야 통과(우연히 맞는 풀이 방지).

30레벨 난이도 사다리

레벨하중상
1~5← → ✋만, 서류 1~2장함수 줄(2번 줄) 첫 등장색 딱지 + 반복 복습
6~10서류 3~4장 옮기기, 칸 넉넉함수 안에서 반복서류 색 3가지(🟨 보류 추가)
11~15‘1’ 반복 카드 첫 등장칸 빠듯 → 함수를 써야만 들어감‘빈손/들고 있음’ 딱지 첫 등장
16~20반복 + 서류 탑 뒤집기🟩/🟥 색 딱지 첫 등장(단순 나누기)시험 2개(서류 수가 다름)
21~25반복 + 칸 빠듯색 + 함수 조합시험 3개 + 칸 아주 빠듯
26~30하의 마무리: 두 탑 합치기색 나누기 + 반복 끝내기정렬형(색별로 여러 칸) + 최소 카드 도전

데이터 형식

level = { title, brief,
  stacks: [["G","R"],[],[]],      // 아래→위, G 승인 · R 반려 · Y 보류
  goal:   [[],[],["R","G"]],
  start: 0, height: 5,             // 로봇 시작 칸, 칸 높이 제한
  rows: [6,4],                     // 프로그램 줄마다 칸 수
  cards: ["L","R","G","F1","F2"],  // 쓸 수 있는 카드
  conds: ["G","R"],                // 쓸 수 있는 딱지 (없으면 [])
  tests: [{stacks, goal}],         // 상 11~: 추가 시험
  par: 8,                          // 별 3번째: 카드 수 목표
  witness: { prog: [[["G"],["R"],["R"],["G"]],[]] } }
draft = { prog: [[ ["G",null], ["F2","R"] ], [ ... ]] }   // [카드, 딱지]

판정·생성·풀이기

  • robotRun(level, prog, test): 단계마다 상태(칸·로봇 위치·집은 서류·호출 스택)를 기록 → 화면 애니메이션과 판정이 같은 함수를 씀. 반환 {ok, steps, trace, failAt, why}.
  • evaluate: 모든 시험이 ok면 valid, metric = 쓴 카드 수(별 3번째 비교용).
  • 생성기(levelgen/gen_work.js → sequence): ① 레벨 단계별 ‘장치 목록’(반복/함수/색/빈손/시험 수)을 정함 → ② 그 장치들로 만든 프로그램 틀(예: “집기 → 색이면 함수 → 반복”)에 무작위 방향·칸 배치를 넣어 시작/목표 모습을 만듦 → ③ 풀이기가 칸 제한 안 카드 조합을 반복 깊이 탐색(가지치기: 상태 중복·쓸모없는 ←→ 연속 제거)해서 최소 카드 수 계산 → ④ 그 장치 없이 풀리면 버림(새 장치 레벨은 꼭 그 장치가 필요) → ⑤ 점수 = 최소 카드 수 × 1.5 + 실행 단계 수 log + 장치 수 × 2.
  • build() 개선: 30개를 점수로만 고르지 않고 5레벨씩 ‘장치 단계’별 후보군에서 5개씩 골라 사다리가 지켜지게.

화면

  • 카드 넣기: 아래 카드 묶음에서 끌어 칸에 놓기 + 칸을 탭한 뒤 카드 탭(끌기가 어려운 사람용). 놓인 카드를 길게 누르면 딱지 고르기, 위로 끌어내면 빼기.
  • 실행: ▶(보통 속도) · ⏩(4배) · 👣 한 단계. 실행 중 카드 노란 테두리, 로봇·서류는 CSS 이동 애니메이션(180ms/단계).
  • 틀리면 그 단계에서 멈추고 말풍선(“반려를 오른쪽에 놓으려 해요!”), 목표 미니 그림에서 다른 칸이 깜빡임.
  • 휴대폰 375px: 서류함 영역 150px, 프로그램 3줄 × 최대 8칸(칸 30px).

힌트·도구·별

  • 힌트 1: 이 레벨의 핵심 장치(예: “반복 카드 ‘1’을 맨 끝에”) · 힌트 2: 정답의 1번 줄 앞 절반 · 힌트 3: 정답 놓기(보조 완료).
  • 도구 ‘실행 미리보기’(4일차 상점) → ‘한 단계씩 보기’ 버튼 해금으로 바꿈(도구 없으면 ▶만). 이름 그대로, 설명 문구만 수정.
  • 별: 완료 · 힌트 없이 · 카드 수 ≤ par.

데이터·엔진

level = { title, brief,
  machines: [{t:"scale", th:100, inc:false}, {t:"dedup", keep:"last"}],   // 고장 난 처음 상태
  slots: 4,                         // 기계 자리 수 (빈 자리 포함)
  spare: ["approve","zero"],        // 끼울 수 있는 기계
  inputs: [{show:true, docs:[{id:"A",amt:120,ok:true}, ...]}, {show:false, docs:[...]}],
  limit: 2,                         // 고칠 수 있는 횟수 (null = 제한 없음, 별 3번째만)
  par: 2, witness: { machines:[...] } }
draft = { machines:[...], edits: 1 }
  • 기존 runMacro를 runLine(machines, docs) → {bins:{boss,chief,trash}|total, path:[문서별 지나간 기계]}로 감쌈. path는 애니메이션과 ‘의심 기계 표시’에 씀.
  • evaluate: 모든 투입 묶음에서 정답 줄(witness)과 같은 통 결과 + 고친 횟수 ≤ limit. 정답 줄과 모양이 달라도 결과가 같으면 정답.
  • 고친 횟수 = 처음 상태와의 ‘편집 거리’(기계 끼우기/빼기/옮기기/설정 바꾸기 각 1). draft에 쌓지 않고 처음 상태와 비교해 계산 → 되돌리면 횟수도 줄어듦.
  • 생성기(gen_brain.js → macro): 정답 줄 무작위(단계별 기계 목록) → 고장 k개 넣기(종류: 빼기·순서·스위치·눈금·끼워 넣기) → 투입 서류 만들기: 고장마다 그 고장만 드러내는 서류를 하나 이상 넣되, 상에선 일부를 숨은 묶음으로 → 풀이기(편집 거리 ≤ k+1 너비 우선 탐색)로 ‘k번보다 적게 고치는 다른 방법’이 없는지 확인 → 점수 = 고장 수 × 3 + 순서 고장 × 2 + 숨은 묶음 × 2 + 탐색 상태 수 log.
  • 정보화팀 ‘정산 매크로’가 쓰던 같은 엔진 생성기(DEPT.it)는 C로 바뀌므로 매크로 전용으로 옮김.

화면·힌트·도구

  • ▶ ‘흘려 보기’: 서류가 한 장씩 벨트를 타고 기계를 지나며(기계가 반짝), 버려질 땐 옆으로 떨어짐. 결과 통에서 틀린 서류만 빨강 ✕. 흘려 보기는 몇 번이든 무료.
  • 틀린 서류를 누르면 그 서류가 지나간 길이 표시됨(“A 99 → 중복 체 통과 → 승인 검사기 통과 → 저울: 계장”). 버그 찾기의 핵심 도구.
  • 도구 ‘경계값 카드’(8일차) → 숨은 묶음 하나를 미리 흘려 보기.
  • 힌트 1: 고장 개수와 종류 하나 · 힌트 2: 고장 난 기계 하나 위치 · 힌트 3: 정답 줄.
  • 별: 완료 · 힌트 없이 · 고친 횟수 ≤ par(최소).
