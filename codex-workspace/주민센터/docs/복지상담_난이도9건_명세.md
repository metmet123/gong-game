# 복지상담 즉시 개방 · 난이도별 9건

2026-10-11 · 사용자가 A(처음부터 정식 복지상담)와 다양한 상·중·하 사례 구현을 지시했다. 이전 전입 첫 근무 후 개방·총 3건 범위를 이 명세로 갱신한다. 따뜻한 생활 이야기, 직접 판단, 선배 정답 비공개, 기존 전입 보존은 유지한다. 공개 배포와 본편 정식 반영은 별도다.

## 게임 규칙

처음부터 정식 복지상담을 시작한다. 하·중·상 각 3건, 총 9건이다. 사례철에서 난이도를 고르고 원하는 사례를 시작하거나 초안을 이어간다. 난이도와 사례 순서에 잠금을 두지 않는다. 진행을 위해 전입 기록을 만들거나 첫 근무를 완료 처리하지 않는다.

난이도는 감점·시간 제한·작은 버튼으로 높이지 않는다. 하에서는 한 가지 현재 필요와 상담 의사를 확인한다. 중에서는 서로 다른 시점과 실제 도움의 범위를 비교한다. 상에서는 여러 문제, 사람별 도움과 동의 범위, 두 근거가 필요한 판단, 우선 연결할 상담을 다룬다. W01은 관계와 도움을 구분하는 입문 사례로 기존 다섯 판단을 보존한다. 더 짧은 하 사례는 W04·W05다.

| 난이도 | ID | 사례 | 핵심 쟁점 |
| --- | --- | --- | --- |
| 하 | W01 | 같은 주소, 다른 하루 | 가족관계·동거·전화·방문 도움·식사 필요를 구분 |
| 하 | W04 | 휴대폰 앞에서 멈춘 신청 | 문자 안내와 신청 완료는 별개, 원하는 대면 도움 확인 |
| 하 | W05 | 식탁 위에 쌓인 고지서 | 전기요금 어려움과 임대료 납부를 구분 |
| 중 | W02 | 끝난 지원, 남아 있는 기록 | 과거 지원과 현재 상태, 기관 확인 대기 |
| 중 | W06 | 금요일까지만 가능한 부탁 | 가족의 일시적 도움, 근무와 돌봄 일정 두 근거 |
| 중 | W07 | 주소에 남아 있는 친구 | 옛 동거 기록과 현재 거주, 불확실한 경제적 도움 |
| 상 | W03 | 한 집의 두 가지 부탁 | 생활비·주거 두 상담, 임시 도움과 우선순위 |
| 상 | W08 | 퇴원 뒤의 빈 시간 | 딸·이웃의 실제 도움, 식사·이동 두 상담과 병원 일정 |
| 상 | W09 | 도움받되 알리고 싶지 않은 일 | 주거·구직 상담 동의와 가족 정보 전달 동의를 구분 |

새 사례의 주민·기관·서비스·처리 기준은 게임용 창작이다. 실제 법정 자격이나 지급 기준을 판정하지 않는다. 실제 지원 승인은 모든 완료 기록에서 false이고 본편 XP·포인트는 지급하지 않는다.

## 플레이와 화면

1. 첫 화면의 첫 업무는 복지상담실이다. 난이도별 완료 수와 전체 완료·초안 수를 보여 준다.
2. ‘첫 상담 시작하기’는 기존 W01로 시작한다. ‘상담 사례 고르기’에서는 전체 9건 또는 하·중·상 3건을 표시한다. 완료·새 상담·작성 중·답신 도착을 구분한다.
3. 자료에서 주민의 첫마디와 원문·작성 시점·적용 시점을 읽는다. 질문 후 답변 원문 상단으로 이동하고 초점을 돌린다. 열람 가능한 자료 수와 전체 자료 수를 구분한다.
4. 질문의 선행 조건을 해당 질문·동의 자료명으로 안내한다. 읽거나 보관하거나 질문해도 판단을 자동 입력하지 않는다.
5. 인물을 선택해 판단과 근거를 연결한다. 두 근거가 필요한 판단은 하나만 연결해서 확정할 수 없다. 오류 검토는 비교할 대상·시점·도움 범위를 안내하고 정답 선택을 대신하지 않는다.
6. 상담과 남은 확인, 필요한 경우 우선순위를 작성한다. 선배 도움은 사례별 확인 방법을 세 단계로 안내한다.
7. 완료 화면에서 주민 반응·내 연결 계획·다음 확인·기념품을 보여 준다. 다음 근무 답신을 확인하고 사례 선택으로 돌아가거나 다음 미완료 상담으로 이어간다.
8. 완료 기록은 열람만 가능하다. 다시 풀기는 체험으로 새로 열며 정식 기록·기념품·답신을 바꾸지 않는다.

모바일 사례철은 한 열, 넓은 화면에서는 두 열이다. 난이도 버튼은 44px 이상이다. 상담은 기존 탭과 목록 대체 조작을 유지한다. PC 판단 58%·자료 42%, 입력 16px, 글자 200% 확대는 구현 기준이며 사용자의 개별 치수 승인으로 기록하지 않는다.

## 기술·저장 계약

- 기존 W01~W03의 ID·자료·질문·판정·완료 스냅샷은 보존한다. 난이도·첫마디·도움 문구는 표시 메타데이터이며 완료 기록에는 추가하지 않는다.
- W04~W09는 `src/welfare/data/extra-cases.js` 한 곳에서 작성한다. `cases.js`가 기존 3건에 추가하며 Node와 브라우저가 동일한 데이터를 사용한다. 빌드는 extra-cases를 먼저 넣는다.
- 새 ID는 `resident-center:welfare:W04`~`W09`. 내부 참조는 사건별 범위에서 검증한다.
- 센터 저장 키·schema/contentVersion 1, 복지 version 1은 유지한다. 기존 3건 완료 백업을 동결 fixture로 검사한다. 구 기록을 재작성하거나 전입 데이터를 임의 생성하지 않는다.
- `drafts[shortId]`는 서로 다른 여러 사례를 동시에 보관한다. 완료 기록은 순서와 무관하게 유효성을 재검증한다. `items`는 사건 데이터 순서의 완료 사례 집합으로 정규화해 완료 순서에 따른 중복을 막는다.
- 답신은 실제 확인 버튼을 누른 뒤에만 한 번 기록한다. `shiftIndex=seenReplyIds.length+1`, 범위 1~10. 전입 `dayClosed`와 별개다.
- 기존 3건 → 새 9건 저장은 호환한다. 새 사례가 포함된 백업을 이전 3건 빌드가 읽는 역방향 호환은 제공하지 않는다. 이전 validator는 읽지 못한 원본을 보호하므로 이전 빌드에서 새 기록을 덮어쓰지 않는다.
- 호스트 Web Locks·revision 충돌·v2 ack·완료 불변성·저장 실패 시 화면 유지·원본 보호·명시적 백업/가져오기는 유지한다. 전입 선행 잠금과 개방 연출은 사용하지 않고 기존 관련 저장 필드는 호환용으로 보존한다.

## 검증 기준과 근거

`welfare-engine.cjs`는 9건의 정상 완주와 기존 대안을 검사한다. `welfare-difficulty.cjs`는 3건씩 배치, 기존 백업, 역순 완료, 여러 초안, 두 근거·미확인 도움·동의 경계의 오판을 검사한다. 브라우저에서는 9건 전부의 자료·질문·근거·계획·인계·답신, 비순차 선택, 새로고침, 실제 JSON 다운로드, 체험 재플레이의 정식 기록 불변을 검사한다.

320×568, 390×844, 430×932, 844×390, 1180×820에서 사례철과 상 난이도 두 근거를 검사하고 320px 200% 확대와 키보드 초점 복귀를 확인한다. 기존 전입 아티팩트가 이전 인수 해시와 같은 경우에만 이전 통과 결과를 명시적으로 재사용한다.

실행 결과는 [센터 검증](센터검증.json), [난이도 엔진](복지9건_엔진검증.json), [사례철·모바일](../design/화면/복지9건/검증.json), [작업 로그](../2._WORK_LOG.md)에 기록한다. 실제 Android/iPhone, 초심자의 난이도 체감·재미, 공개 배포와 본편 통합은 이 자동 검증에 포함하지 않는다.
