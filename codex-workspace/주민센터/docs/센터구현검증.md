# 복지상담 우선 · 두 업무 실제 구현 계약

2026-10-11. 최신 사용자 지시: A(처음부터 정식 복지상담), 다양한 난이도별 여러 건. 하·중·상 각 3건 총 9건으로 로컬 구현. 자동 검증 결과는 센터검증.json을 따른다. 공개·본편·실제 기기·초심자 평가는 미실시.

현재 추가 명세: [난이도별 9건](복지상담_난이도9건_명세.md). 이전 첫 근무 후 개방·3건 계약은 사용자 후속 지시로 대체했다.

## 실행과 빌드

- 실행판: [주민센터 두 업무](../주민센터_두업무.html). 파일 직접 열기 가능. 저장 인수는 localhost/HTTPS에서 수행했다. 저장 기능이 제한된 환경은 메모리 진행과 백업으로 안내한다.
- 처음부터 정식 복지상담을 시작한다. 전입 선행 조건과 개방 연출은 제거한다. 전입 접수·근무 결산 기록을 임의 생성하지 않는다. 첫 화면 복지가 먼저이며 사례철에서 하·중·상 각 3건을 자유 선택한다.
- W01 빠른 체험과 사례별 체험 재플레이가 가능하다. 체험 결과·기념품·답신은 정식 센터 기록에 포함하지 않는다.
- 기존 전입 공개 URL은 변경하지 않았다. 기준 사본은 [기존 공개 전입](센터기준/기존공개전입.html), 보존 근거는 [기준](센터기준.json). CRLF를 맞추면 작업 시작 시 전입 해시와 일치한다.
- `python build_puzzle.py`, `python build_integrated.py`: 기존 독립 전입·로컬 본편 후보 재생성. 루트 게임 소스는 수정하지 않았다.
- `python build_center.py`: 새 `주민센터_두업무.html`, `preview-center/index.html`, 실제 조작 가능한 `design/두업무_구현비교.html` 생성. 외부 폰트·CDN·이미지·서버 의존성 없음.
- `python tests/run_center_checks.py --browser`: 신규/기존 회귀 실행. Playwright와 Edge가 필요하다. `--reuse-legacy-report`는 동일한 기존 아티팩트에 대한 통과 인수 결과만 재사용하며 보고서에 재사용임을 표시한다.

## 전입창구 보완

첫 접수 시작 문구에서 주민은 이미 이사했고 직원은 주소 기록을 바꾸는 업무임을 설명한다. 작업 화면에 ‘이사한 사람 기록 → 관계 기준 선택 → 기준과의 관계 작성’을 표시한다. 선택한 단계에는 ‘선택함 · 정답 검토 전’을 표시한다. 선택한 사람·관계·이유와 오답은 그대로 남고 선배 도움은 정답 이름을 말하지 않는다.

기존 6사례·4일 12방문·M06 보완 재방문·세대 기록·기념품·본편 후보 180XP/300포인트 및 중복 방지 계약을 유지했다. 기존 진행 중 M01에 첫 접수를 강제 삽입하지 않는다. 구 저장 키는 `gong-game:resident-center:v1`이고 기존 validator를 유지한다.

## 센터 저장과 통신

새 키는 `gong-game:resident-center:hub:v1`, schema/contentVersion 1이다. 기존 전입 모델을 `moveIn`에 포함하고 복지는 `welfare`에 별도로 둔다. 원래 독립 전입 키와 본편 키를 읽거나 쓰는 작업은 명시적 구 전입 가져오기 읽기 외에는 하지 않는다.

호스트만 저장을 쓴다. 한 iframe만 활성화한다. 전입·복지 자식은 opaque sandbox(`allow-scripts allow-downloads`)에서 메모리로 진행한다. v2 메시지는 channel/protocol/token/requestId/seq, 활성 iframe source와 모델 validator를 확인한다. 중복 요청은 같은 내용에만 같은 결과를 반환하며, 이미 완료된 기록을 자식이 변경·삭제하려는 요청은 거부한다.

자식이 ‘저장됨’을 표시하기 전에 부모의 ack를 확인한다. 업무 전환은 입력을 잠시 중지하고 flush 요청의 저장 결과를 기다린다. 3초 이상 확인되지 않거나 저장이 실패하면 화면을 유지하고 재시도·초안 백업을 제공한다. ‘백업하고 업무 선택으로’는 백업을 내보낸 뒤 미저장 안내를 유지한다.

저장 읽기·revision 대조·쓰기 전체를 Web Locks의 exclusive lock 안에서 수행한다. Web Locks 미지원은 메모리 진행으로 안내하며 저장 완료라고 표시하지 않는다. 용량 실패·다른 창 충돌·손상·미지원 버전을 원본 보존과 함께 처리한다. 원본 내보내기 전에는 손상 저장 복구를 실행하지 않는다. 저장 getter 자체가 거부되는 환경도 로딩 오류로 화면 전체를 중단하지 않는다.

가져오기는 미리보기·취소·현재 센터 백업·적용의 흐름이다. 구 전입 가져오기는 복지 기록을 보존한다. 전입 진행과 무관하게 신규 복지 접수가 가능하며 기존 초안과 기록을 유지한다. 센터 백업 가져오기는 전체 교체이며 새 저장 revision은 현재 브라우저의 revision에서 이어간다. 지원하지 않는 백업은 적용하지 않는다.

## 복지 순수 엔진과 사건

`session.js`(초기 상태·자료 접근), `review.js`(근거/판단/계획), `resolve.js`(완료 스냅샷), `actions.js`(순수 전이), `services/storage.js`(세션·완료·진행 검증)로 분리했다. UI는 정답을 판정하지 않는다.

자료 열람·원문 보관·질문은 답을 채우지 않는다. 질문이 열어 준 답변은 별도 자료로 읽으며 상단과 키보드 초점으로 이동한다. 잠긴 질문은 해당 선행 질문·동의 자료명을 안내한다. 선배 도움은 사례별 확인 방법을 설명하며 답을 입력하지 않는다. 연락 동의가 필요한 질문은 원문 보관 후 가능하다. 주장·근거·질문·계획 변경은 검토를 무효화하고, 보관 해제는 선택 값을 남긴 채 연결 근거만 제거한다. 선택한 근거는 해당 자료가 실제로 공개되고 읽힌 원문인지 확인한다.

- **W01 같은 주소, 다른 하루**: 가족관계·현재 동거·전화·매일 방문·식사 준비를 구분한다. 현재 동거 근거 두 경로와 전화 연락의 협력 메모 대안을 인정한다. 첫 인물 카드에 가족관계의 정답을 역할명으로 미리 표시하지 않는다. 완료는 동의 기반 식사 상담 의뢰이며 실제 서비스 승인 여부는 false다.
- **W02 끝난 지원, 남아 있는 기록**: 과거 지원과 현재 종료를 분리한다. 기본 경로는 기관 종료 확인 후 상담 의뢰다. 데이터의 `agencyPending:true` fixture는 미도착 답변을 읽을 수 없고, 질문 요청·확인 필요·구체적인 다음 근무일 확인 계획으로 인계할 수 있다. 이 분기는 엔진과 실제 UI로 검증했으며 기본 새 사건은 즉시 확인 경로다.
- **W03 한 집의 두 가지 부탁**: 생활비·주거 두 상담, 임시 가족 도움, 지속 가능 여부 확인 필요를 구분한다. 주민이 말한 기한을 근거로 주거 상담을 먼저 연결한다. 생활보장과는 일반 역할명으로 등장하며 다른 섹션 캐릭터 설정을 임의 수정하지 않았다.

W04~W09는 디지털 도움·공과금·돌봄·주거와 친구의 도움·퇴원 후 식사/이동·주거/구직과 동의 범위를 다룬다. 사례별 핵심 쟁점과 난이도는 [9건 명세](복지상담_난이도9건_명세.md)를 따른다.

복지 상태의 `active`는 현재 shortId다. `drafts[shortId]`에 여러 사례의 실제 세션을 함께 보관하고 비순차 완료를 허용한다. 완료 시 `records[shortId]`의 불변 스냅샷으로 옮긴다. 정식 완료만 사건별 기념품을 1회 지급한다. `shiftIndex`는 복지 근무이며 전입 `dayClosed`와 다르다. 다음 상담 버튼에서 답신을 보여 주고 확인 버튼을 누른 뒤 `seenReplyIds`와 근무를 한 번 증가시킨다. 답신 확인 후 사례 선택으로 돌아가거나 다음 미완료 상담으로 이어간다. 답신 한 번당 shiftIndex가 증가하며 최대 10이다. 기념품은 사건 데이터 순서로 정규화한다. 기존 3건 완료 백업과 오답 검토 문구를 보존한다.

## 모바일과 실제 화면

기존 전입의 베이지·녹색과 복지의 회청색·남색을 구분했다. 모바일은 자료/관계·상황/연결 계획 탭, PC는 편집 58%·자료 42% 동시 패널이다. 인물 관계망 대신 목록으로 조작할 수 있다. 판단 카드에는 연결한 원문만 표시하고, 보관 근거 선택은 별도 창으로 열어 중복 긴 목록을 줄였다. 선택은 즉시 초안에 반영되며 검토 전까지 미확정이다.

44px 이상 조작, 16px 입력, 내부 스크롤·고정 주요 행동·키보드 탭 이동·dialog Escape·초점 복귀·200% 글자 확대를 검증했다. 이전 시안 수치를 그대로 적용한 구현 기준이며, 사용자가 치수별 수치를 직접 승인했다고 기록하지 않는다.
