### 결과 답변

저라면 **공문은 ‘정확하게 전달하기’, 예산은 ‘한정된 자원으로 실행하기’, 민원은 ‘문제의 원인을 찾아 해결하기’**로 역할을 나누겠습니다. 그리고 세 축을 **하나의 사건으로 연결**하겠습니다.

지금 연습실에 여러 퍼즐이 있으니, 기존 퍼즐을 실제 업무의 단계로 묶으면 “내가 왜 이 문제를 푸는지”가 더 선명해질 것 같습니다.

| 축 | 플레이어가 고민할 것 | 기존 퍼즐 연결 | 확장할 핵심 재미 |
|---|---|---|---|
| 공문 | 무엇을, 누구에게, 어떤 근거로 전달할까? | 서류 검토·자료 취합·한 장 보고·결재 동선 | 자료를 읽고 필요한 내용을 골라 문서를 완성하기 |
| 예산 | 언제, 어디에, 얼마나 사용할까? | 예산 테트리스·매크로·자료 취합 | 계획과 실제 집행을 맞추고 부족·중복·오류를 해결하기 |
| 민원해결 | 이 사람의 진짜 요청은 무엇이며, 무엇을 확인해야 할까? | 전화 메모·서류 주인·담당부서 안내·부서 미니게임 | 단서를 모으고 협조를 받아 결과까지 확인하기 |

**공문은 ‘문서 한 건을 완성하는 과정’으로 확장하면 좋겠습니다.**

접수된 요청을 읽고 → 근거 자료를 찾고 → 본문과 붙임을 구성하고 → 결재·발송하는 흐름입니다. 화면에는 실제로 완성 중인 공문이 보이고, 퍼즐을 풀면 해당 부분이 채워집니다.

- **초반:** 날짜·금액·수신처 오류 찾기, 올바른 붙임 고르기.
- **중반:** 여러 자료에서 목적·기한·담당 내용을 뽑아 본문 구성하기.
- **후반:** 서로 다른 요청을 한 문서에 정리하고, 출장·회신 기한을 고려해 결재와 발송 순서 짜기.

예를 들어 “지원사업 실적을 금요일까지 제출해 주세요”라는 요청에서 **최신 승인 자료 선택 → 보고서 압축 → 결재 일정 배치**가 연결됩니다. 긴 문장을 직접 타이핑하기보다는 문장 카드와 문서 칸을 사용하면 모바일에서도 편하게 풀 수 있습니다.

**예산은 ‘편성 → 집행 → 정산’의 세 단계로 넓히겠습니다.**

현재 예산 테트리스가 배치의 재미를 맡는다면, 앞뒤에 돈의 흐름을 붙이는 방식입니다.

| 단계 | 업무 예시 | 조작 방식 |
|---|---|---|
| 편성 | 필수 사업을 포함해 월별 한도 안에 계획 세우기 | 사업 카드·기간 블록 배치 |
| 집행 | 지출 요청을 맞는 사업·항목에 연결하기 | 요청서와 예산 항목 짝짓기 |
| 정산 | 승인 내역·영수증·지급액의 불일치 찾기 | 대조표 수정·중복 제거·합산 |

특히 **“잔액은 있는데 해당 항목에는 쓸 수 없다”**, **“같은 청구가 두 번 들어왔다”**, **“사업 일정이 바뀌어 집행 월을 옮겨야 한다”** 같은 상황은 기존 퍼즐과 잘 어울립니다.

사업 예산은 별도의 업무용 숫자로 두고, 소품을 사는 개인 포인트와 구분하는 게 좋겠습니다. 또한 필수 조건을 만족하는 계획은 여러 개 허용하고, 더 효율적인 배분은 추가 도전으로 두면 부담을 조절할 수 있습니다.

**민원은 ‘접수 후 결과가 돌아오는 사건’으로 확장하는 것을 추천합니다.**

담당부서만 골랐다고 끝내기보다 다음 흐름을 만들면 주민과 동료가 기억에 남습니다.

**이야기 듣기 → 요청 정리 → 자료·현장 확인 → 협조 요청 → 처리안 마련 → 결과 안내**

여기서 핵심은 대화 선택마다 숨은 정답을 두는 것보다, **확인한 사실을 바탕으로 해결하도록 만드는 것**입니다.

- “답장이 안 왔어요.” → 접수 기록과 발송 내역을 비교한다.
- “안내문마다 날짜가 달라요.” → 적용 시점과 최신 공지를 확인한다.
- “물품을 받기로 했는데 누락됐어요.” → 신청 명단·출고 기록·수령 기록을 맞춘다.
- “우리 동네 시설이 불편해요.” → 현장 확인 후 관련 부서와 실행 계획을 세운다.

처리 뒤에는 다음 날 짧은 회신이나 변화가 보이면 좋겠습니다. 다만 해결에 외부 협조가 필요한 사건은 **접수 완료·조치 예정·최종 해결**을 구분해서, 플레이어가 한 일과 결과가 자연스럽게 이어지도록 합니다.

세 축을 연결하는 첫 사례로는 **‘주민센터 안내문과 물품 배부가 엇갈린 사건’**을 추천합니다.

| 흐름 | 플레이 내용 | 다음 단계에 남는 결과 |
|---|---|---|
| 민원 접수 | 주민의 말과 배부 기록에서 누락 원인 찾기 | 필요한 물품 수량·잘못된 안내 내용 |
| 예산 처리 | 추가 물품 구입 계획과 중복 청구 확인 | 확정 금액·구입 일정 |
| 공문 처리 | 수정 안내문과 협조 공문 작성·결재 | 배부 일정·담당자·안내 내용 |
| 후속 소식 | 주민의 수령 확인과 동료의 답장 | 사건 종결 기록·인물 대사 |

앞 단계의 결과를 다음 화면에서 실제로 사용해야 연결감이 생깁니다. 찾은 수량이 예산표에 들어가고, 확정된 일정이 공문에 들어가는 식입니다.

처음에는 **짧은 단일 업무와 2~3일에 걸친 연결 사건을 섞는 방식**이 좋겠습니다. 하루 4건이라는 기존 계획은 유지하면서, 그중 일부를 연결 사건의 단계로 배정하면 됩니다. 한 사건의 모든 단계를 하루에 몰아넣을 필요는 없습니다.

첫 확장은 **공문 완성 화면, 예산 집행·정산 화면, 민원 사건철**을 작은 범위로 만들고, 위 연결 사건 한 편을 끝까지 체험하게 하는 순서를 추천합니다. 그 한 편에서 재미와 조작을 확인한 뒤, 같은 구조에 새로운 사건과 조건을 추가하면 세 축이 함께 성장할 수 있습니다.

## 작업 4 · completed

### 사용자 요청

방향은 좋은 것 같은데 기존 퍼즐과 연결하지 않고 새로운 퍼즐을 만드는 방식도 생각중이야.

&#x20;아래와 같은 방식을 추가하는 건 어때?&#x20;



**플레이어가 돈·서류·사람을 직접 움직이고, 그 결과로 사무실과 사업이 달라지는 방식**을 추천해. 공문은 실제 기안문 모습을 유지하되, 그 안에서 게임이 벌어지게 하는 거야.

예산 3개 챕터를 **편성은 전략, 지출은 작전 수행, 결산은 탐정 게임**으로 잡으면 차이가 뚜렷해져.

### 1. 예산편성 — 「예산 쟁탈전」

**한정된 예산으로 이번 해의 사업 덱을 만드는 게임.**

화면에는 홍보물·복지교육·안내판 등의 사업 카드와 예산 칩이 놓여 있어. 카드를 선택해 예산요구서에 배치하면 사업이 활성화되고, 조합에 따라 효과가 생겨.

| 게임 요소 | 구체적인 방식                                |
| ----- | -------------------------------------- |
| 사업 카드 | 비용·효과·필수 조건이 서로 다름                     |
| 예산 칩  | 사업에 배치해 규모 결정. 일부는 예비로 남길 수 있음         |
| 조합 효과 | 홍보물＋안내판을 함께 편성하면 ‘안내 강화’ 효과            |
| 돌발 카드 | “인쇄비 상승”, “추가 수요 발생”, “요구액 조정”으로 계획 변화 |
| 결과    | 선택한 사업이 이후 지출 미션과 사무실 변화로 등장           |

예를 들어 예산 칩 10개를 가지고 홍보물에 4개, 교육에 3개, 안내판에 2개를 배치하고 1개를 남겨. 이후 ‘인쇄비 상승’ 사건이 나오면 남겨둔 칩으로 대응하거나 사업 규모를 조정하는 거지.

**많이 편성했다고 무조건 좋은 결과가 나오지 않게** 하자. 사업을 많이 선택하면 보상도 커지지만, 이후 처리할 업무도 늘어나는 구조가 재미있어.

추경은 별도의 계산 문제가 아니라 **진행 중인 사업 덱을 다시 짜는 중간 이벤트**로 넣으면 자연스러워.

### 2. 예산 지출 — 「결재 작전」

**서류철 하나를 들고 사무실을 돌아다니며 업무를 완수하는 게임.**

책상에서 기안하고, 동료에게 협조받고, 프린터에서 붙임을 챙기고, 결재를 받은 뒤 납품을 확인해. 기존에 구상한 사무실 이동과 가장 잘 연결되는 챕터야.

| 미니게임   | 실제 조작                        | 게임다운 재미                        |
| ------ | ---------------------------- | ------------------------------ |
| 공문 조립  | 제목·본문·붙임 조각을 문서의 알맞은 위치에 끼우기 | 예전 문서 조각이 섞여 있어 관찰 필요          |
| 결재 동선  | NPC 일정과 협조 조건을 보고 방문 순서 선택   | 자리에 없는 팀장, 먼저 필요한 협조 등으로 경로 변화 |
| 프린터 소동 | 출력되는 서류 중 내 사업의 최신본만 챙기기     | 다른 직원 서류와 구버전이 섞이는 짧은 순발력 게임   |
| 납품 검수  | 주문서와 실제 물품을 나란히 놓고 불일치 표시    | 수량 부족·잘못된 규격·다른 사업 물품 발견       |
| 지급 마무리 | 확인된 증빙을 서류철에 넣고 지급 진행        | 앞서 놓친 부분이 마지막에 드러남             |

**결재는 타이밍에 맞춰 도장을 누르는 것보다, 조건을 풀어 도장 칸을 하나씩 채우는 방식**이 좋아. 도장이 찍힐 때마다 소리와 애니메이션으로 진행감을 주고, 반려되면 문서에 빨간 메모가 붙어 돌아오는 거야.

실수해도 처음부터 다시 하지 않아. 잘못 붙인 견적서만 바꾸거나, 부족한 납품을 보완받으면 이어서 진행할 수 있어.

### 3. 예산 결산 — 「사라진 22만원」

**내가 처리했던 사업 기록을 사건 보드에 펼쳐놓고, 맞지 않는 숫자의 원인을 찾는 게임.**

단순 합산 대신 거래·문서·NPC 메모를 연결해 사건을 해결하게 하자.

| 게임 요소 | 구체적인 방식                       |
| ----- | ----------------------------- |
| 사건 보드 | 예산표·지급 기록·취소 문서·납품 자료를 카드로 배치 |
| 단서 연결 | 같은 거래번호나 사업명을 가진 자료를 선으로 연결   |
| 용의 기록 | 중복·취소·누락이 의심되는 기록에 표시         |
| 추가 조사 | 동료에게 질문하거나 보관함에서 수정본 찾기       |
| 해결    | 오류 원인을 밝히고 결산보고서의 해당 칸 수정     |

예를 들어 집행표에는 44만원이 적혀 있지만, 실제 지급은 22만원이야. 금액이 같은 카드 두 장을 찾았다고 바로 하나를 지우면 안 돼. 거래번호와 지급 상태를 확인해 **같은 지급이 두 번 기록됐다는 증거**를 찾아야 해결되는 거지.

마지막에는 공문에 직접 ‘조사 결과’를 끼워 넣고 결재받아 사건을 닫아. **편성에서 고른 사업과 지출에서 만든 문서가 다시 단서로 등장**하면 플레이어의 행동이 쌓였다는 느낌이 생겨.

### 4. 공문 자체도 게임판으로 만들기

공문을 읽고 아래 정답 버튼만 누르게 하지 말고, **문서 위에서 직접 조작**하게 하자.

- **본문:** 문구 조각을 끼우면 번호식 문장이 완성됨.
- **금액:** 참고자료의 숫자를 가져와 산출기초와 연결.
- **붙임:** 서류를 문서 아래에 겹쳐 놓으면 클립으로 묶임.
- **결재란:** 조건을 충족할 때마다 도장이 하나씩 찍힘.
- **반려 메모:** 해당 위치에 붙어 있고, 수정하면 떼어낼 수 있음.

기본 외형은 실제 공문처럼 차분하게 두고, **종이 넘김·클립·도장·빨간 메모의 움직임**으로 게임 느낌을 주는 게 잘 어울려.

### 5. 먼저 만들면 좋을 한 편

\*\*「홍보물 200부, 오늘 안에 끝내라고요?」\*\*를 첫 시범 에피소드로 추천해.

| 장면     | 플레이                             |
| ------ | ------------------------------- |
| 편성     | 사업 카드와 예산 칩으로 홍보물 규모 결정         |
| 기안     | 이전 문서를 고쳐 제작계획 공문 완성            |
| 사무실 이동 | 협조 담당자와 결재자를 찾아 서류철 전달          |
| 돌발 상황  | 프린터에서 내 최신 견적서 골라내기             |
| 검수     | 납품된 상자를 열어 수량·규격 대조             |
| 결산     | 중복 지급 기록을 추적해 잔액 확정             |
| 보상     | 완성한 홍보물이 사무실 게시판에 등장하고 문서 도감 등록 |

**업무를 끝낸 흔적이 사무실에 남는 것**이 핵심이야. 숫자 보상만 받는 것보다 안내판이 설치되고, 서류철이 도감에 꽂히고, 동료의 대사가 바뀌면 훨씬 게임답게 느껴질 거야.


### 결과 답변

이 방향이 좋습니다. 특히 **편성에서 선택한 사업이 지출의 미션이 되고, 그때 만든 문서가 결산의 증거로 돌아오는 구조**가 강점입니다. 플레이어가 만든 결과를 다음 챕터에서 다시 다루기 때문에, 업무 전체가 하나의 게임으로 이어집니다.

앞서 제안한 확장안을 이 방향으로 바꾸겠습니다. **새로운 퍼즐의 중심을 ‘사업·문서·사건의 상태를 직접 바꾸는 조작’에 두는 것**이 좋겠습니다.

다만 실제로 재미있게 만들려면 아래 부분을 다듬어야 합니다.

**1. 예산편성은 ‘사업 수’보다 ‘사업의 성격’을 선택하게 하면 좋겠습니다.**

“많이 편성하면 업무가 늘어난다”만 적용하면 적게 선택하는 게 가장 편한 답이 될 수 있습니다. 선택에 따라 **다른 사건과 장면이 열리도록** 만드는 편이 좋겠습니다.

| 편성 선택 | 이후 플레이 변화 | 남는 흔적 |
|---|---|---|
| 홍보물 중심 | 문안·인쇄·배부 문제가 등장 | 게시판과 배부대 변화 |
| 교육 중심 | 강사·장소·참석자 조율이 등장 | 교육 사진·동료 대사 |
| 안내판 중심 | 설치 위치·문구·현장 확인이 등장 | 사무실·지역 장면 변화 |
| 예비비 확보 | 돌발 상황에서 조정 선택지가 생김 | 대응 기록 |

어느 선택에도 장점이 있고, 필수 목표를 만족하는 여러 사업 조합이 가능해야 합니다. ‘쟁탈전’이라는 이름을 유지한다면 동료들의 예산 요구와 조정 과정도 있어야 제목과 플레이가 맞겠습니다.

돌발 사건은 완전한 기습보다 **“인쇄비 변동 가능” 같은 예고를 보고 대비하는 방식**이 전략과 잘 맞습니다.

**2. 지출의 재미는 ‘사무실 걷기’보다 ‘서류철이 변하는 과정’에 두겠습니다.**

서류철을 이 챕터의 중심 물건으로 만들면 좋겠습니다. 안에 들어 있는 문서·붙임·협조 메모·도장 상태가 계속 보이고, NPC에게 건넬 때 그 내용에 따라 반응이 달라지는 것입니다.

예를 들어:

- 협조 담당자가 문안에 수정 메모를 붙인다.
- 견적을 바꾸면 기안문의 금액도 다시 확인해야 한다.
- 결재 후 수량을 바꾸면 관련 부분에 재확인 표시가 생긴다.
- 납품이 부족하면 부족분만 보완받고 이어서 진행한다.

이렇게 하면 방문 순서는 의미 있는 선택이 됩니다. 같은 길을 반복하는 구간은 빠른 전달을 허용하고, 새로운 상황이 생긴 방문에서 대화와 조작을 보여주는 편이 좋겠습니다.

프린터 소동은 잘 어울리지만, **속도 때문에 중요한 증빙을 영구적으로 잃지는 않게** 하겠습니다. 놓친 종이는 출력함에서 다시 찾을 수 있고, 빠른 처리는 별도 기록으로 남기는 정도가 적당합니다.

**3. 결산은 ‘틀린 카드 찾기’에서 한 걸음 더 나아가, 원인을 설명하는 퍼즐로 만들겠습니다.**

사건을 닫으려면 다음 세 가지를 모두 완성하게 하는 것입니다.

| 제출할 것 | 예시 |
|---|---|
| 오류 주장 | 같은 지급이 집행표에 두 번 반영되었다. |
| 근거 연결 | 동일 거래번호의 집행 기록 2장과 실제 지급 기록 1장 |
| 수정 결과 | 집행액을 44만 원에서 22만 원으로 수정한다. |

금액이 같은 것만으로는 증거가 부족하고, 거래번호·상태·수정 이력이 맞아야 합니다. 잘못 연결했을 때도 “틀렸습니다” 대신 **“금액은 같지만 서로 다른 거래입니다”**처럼 조사 방향을 알려주면 좋겠습니다.

또한 결산에서 항상 플레이어의 실수를 찾아내면 앞 챕터의 성공감이 약해집니다. 취소본의 이중 반영, 전달 중 누락, 시스템 기록 오류 등도 섞고, **오류가 없는 사건에서는 정상임을 증명하는 결말**도 넣겠습니다.

**4. 공문을 게임판으로 만드는 방식은 유지하되, 조각마다 의미가 있어야 합니다.**

단순히 모양이 맞는 빈칸에 넣는 퍼즐보다, **문서 내부의 연결 관계를 만드는 퍼즐**이 더 오래 갈 수 있습니다.

- 본문의 사업명이 붙임의 사업과 연결된다.
- 수량×단가가 금액과 연결된다.
- 요청 기한이 실행 일정과 연결된다.
- 수정한 항목에 따라 필요한 재확인이 달라진다.

플레이어가 참고자료의 숫자를 가져와 산출기초에 놓으면 연결선과 계산 결과가 나타나고, 붙임을 끼우면 본문의 붙임 표기도 채워지는 식입니다. 차분한 공문 외형 안에서 충분히 게임이 벌어질 수 있습니다.

모바일에서는 **조각 선택 → 문서 위치 탭**으로도 모든 조작이 가능하게 하면 좋겠습니다.

**5. 세 번째 축인 민원해결에도 독립적인 새 퍼즐이 필요합니다.**

지금 제안은 예산의 세 챕터와 공문 작업이 구체적입니다. 민원은 **‘말·기록·현장을 맞춰 해결안을 만드는 사건 퍼즐’**로 확장하면 균형이 맞겠습니다.

예를 들어 주민은 “홍보물을 못 받았다”고 말하지만, 기록에는 배부 완료로 되어 있습니다. 플레이어가 배부 구역, 수령 명단, 담당자 메모를 조사하면 **다른 장소에 일괄 배송된 물품을 개인 배부 완료로 기록한 원인**을 발견합니다.

그다음 단순히 원인을 고르는 데서 끝내지 않고, 재배부 장소·안내 방법·담당자를 배치해 해결안을 실행합니다. 결과가 다음 날 주민의 답장과 현장 변화로 돌아오면 민원도 하나의 완성된 축이 됩니다.

첫 시범작은 제안하신 **「홍보물 200부, 오늘 안에 끝내라고요?」**가 적합합니다. 다만 200부가 고정 목표라면 편성에서는 제작 방식·배부 방식·예비비를 선택하게 하고, 수량 자체를 선택하게 한다면 제목도 선택한 규모에 맞춰 바꾸겠습니다.

첫 편의 핵심 검증은 이 세 가지면 충분합니다.

- **내 편성 선택이 다음 미션을 바꾸는가?**
- **내가 만든 공문과 서류철이 끝까지 이어지는가?**
- **완료한 사업의 흔적이 사무실과 사람에게 남는가?**

이 세 가지를 한 편에서 구현하면, 이후에는 사업과 민원 사건을 추가하면서 게임의 깊이를 늘릴 수 있습니다.

## 작업 5 · completed

### 사용자 요청

좋아. 「홍보물 200부, 오늘 안에 끝내라고요?」를 첫 시범 에피소드로 해서, 예산편성부터 공문·지출·민원해결·결산까지 화면과 조작 방식, 판정 조건을 구체적으로 기획해줘.


### 진행 안내

첫 시범 에피소드를 시작부터 끝까지 플레이할 수 있는 기획서로 작성하겠습니다. 화면 구성, 모바일 조작, 단계별 판정과 재시도 방식, 앞 단계의 선택이 다음 단계에 미치는 영향을 구체적으로 정리하겠습니다.


### 진행 안내

기획서는 기존 문서 폴더에 별도 파일로 남기겠습니다. `write-page` 스킬을 적용해 읽기 쉬운 문서로 정리하고, 화면 배치를 비교할 수 있는 HTML 시안도 함께 만들겠습니다.

수량은 200부로 고정하고, 편성에서는 안내판·배송·사전 검토와 예비비를 선택하게 하겠습니다. 선택한 옵션은 이후 문서, 이동 경로, 조사 단서와 사무실 변화에 반영하겠습니다.


### 진행 안내

에피소드의 금액과 사건 흐름을 구체화했습니다. 총예산은 26만 원, 제작비는 20만 원에서 22만 원으로 오르고, 선택 사업을 조정해 한도 안에 맞추게 됩니다.

납품된 200부 중 구버전 40부는 무료로 교체하고, 이후에는 중간 보관실에 남은 40부를 찾아 배부합니다. 결산에서는 실제 지급액을 유지한 채, 같은 22만 원이 집계표에 두 번 반영된 원인을 증명하도록 구성했습니다.


### 진행 안내

8개 주요 화면의 조작과 판정 조건을 문서와 시안에 정리했습니다. 오답은 초안을 유지하고 해당 부분만 수정하며, 확인 후 내용을 바꾸면 다시 확인하도록 했습니다.

배송 선택 경로는 제작비 지급 → 배부·민원 해결 → 배송비 지급 순서로 구분했습니다. 금액과 수량 보존 계산은 통과했고, 이제 화면 시안의 가독성을 확인하겠습니다.


### 결과 답변

**상세기획서와 8개 화면 시안을 만들었습니다.** 기존 퍼즐과 별도로, 사업 선택·문서 조립·물품 이동·증거 연결을 중심으로 설계했습니다.

**200부 제작은 고정 목표**입니다. 총예산 26만 원 안에서 안내 거치대·분점 배송·사전 교정과 예비비를 선택합니다. 제작비가 20만 원에서 22만 원으로 오르면 계획을 조정하고, 확정한 선택이 이후 자료·담당자·사무실 변화에 반영됩니다.

| 단계와 화면 | 직접 하는 조작 | 핵심 완료 조건 |
|---|---|---|
| **① 예산편성 보드** | 사업 카드에 예산 칩 배치, 예비비 이동, 선택 사업 회수 | 제작 22칩과 선택 사업·예비의 합이 26칩 |

| **③ 결재 작전** | 서류철 전달, 최신 출력물 확보, 협조와 결재 순서 선택 | 협조·붙임 완비 후 계장→과장 도장 |

결산의 **‘사라진 22만 원’은 실제 지급 오류가 아니라 집계 오류**입니다. 거래번호와 지급확인증으로 같은 지급이 두 번 반영됐다는 사실을 증명해야 합니다. 금액이 같다는 이유만으로 기록을 제외하면 통과하지 않습니다.

모든 화면은 **선택→목적지 탭**으로 조작합니다. 확인과 확정을 구분하고, 수정하면 다시 확인해야 합니다. 실수한 부분만 고치며, 놓친 출력물은 다시 찾을 수 있습니다. 실제 시간 제한은 없고, 전체 플레이는 **17~24분을 목표**로 잡았습니다.

네 가지 최종 선택 경로의 금액과 물품 수량 보존 계산은 검증했습니다. 현재 결과물은 **기획·정적 화면 시안**이며, 게임 구현과 모바일 실기 검증은 아직입니다. HTML의 브라우저 시각 점검도 연결 문제로 완료하지 못했습니다.

**1. Papers, Please — 공문을 ‘직접 만지는 게임판’으로**

![Papers, Please의 서류 검사 작업대](https://shared.akamai.steamstatic.com/store_item_assets/steam/apps/239030/ss_d24155eecb65aaff7367b791bc7d4910fe59b303.1920x1080.jpg)

출입국 심사관이 여러 서류를 확인하고 입국 여부를 결정하는 게임입니다. 화면 속 작업대에 서류가 겹쳐 놓이면서, 문서를 살펴보는 행위 자체가 플레이가 됩니다. [공식 소개](https://papersplea.se/presskit/)

**우리 게임에 적용하면**

- 책상 위에 **제작계획 공문·견적서·이전 사업 문서**를 펼칩니다.
- 견적서의 `200부 × 1,100원`과 공문의 `200부 × 1,000원`을 차례로 누르면 두 항목이 연결되고 불일치가 표시됩니다.
- 잘못된 붙임을 빼고 최신 견적서를 끼운 뒤, 서류철을 묶어 결재에 올립니다.
- 반려되면 문제 지점에 빨간 메모가 붙고, 수정하면 메모를 떼어낼 수 있습니다.

**가져올 핵심은 ‘정답 버튼’보다 서류를 비교하고 고치는 조작입니다.** 도장은 그 작업을 마쳤다는 보상이 됩니다.

**2. Stacklands — 예산편성을 ‘사업을 작동시키는 카드 게임’으로**

**우리 게임에 적용하면**

편성 화면의 선택이 이후 사무실에 **사람·장비·업무로 나타나야** 전략을 세웠다는 느낌이 납니다. 예산표의 숫자만 바뀌는 것보다 훨씬 강한 연결입니다.

**3. Sticky Business — 홍보물 제작·검수를 ‘손으로 완성하는 작업’으로**

![Sticky Business의 주문 포장 화면](https://spellgardengames.com/press/Sticky%20Business/images/07_Packing.jpg)

스티커를 만들고 주문을 포장하며 고객의 이야기를 듣는 게임입니다. 화면 중앙의 상자, 주변의 재료, 고객의 요청이 하나의 작업 공간에 함께 놓입니다. [공식 소개·이미지 출처](https://spellgardengames.com/press/sheet.php?p=Sticky+Business)

**우리 게임에 적용하면**

**우리 게임의 기본적인 화면 분위기와 손맛은 이쪽을 가장 추천합니다.** 차분하고 귀여운 사무실 안에서 종이를 펼치고, 묶고, 상자에 넣는 동작만으로도 업무가 게임처럼 느껴질 수 있습니다.

## My request for Codex:

화면도 실제 게임처럼 느껴지도록 디자인해
참고로 붙임 파일은 다른 퍼즐의 개선 시안이야. 현재 화면과 비교해서 내가 원하는 게 어떤 방향인지 생각해봐

### 진행 안내

붙임 시안 네 개를 현재 화면과 비교해, 원하시는 게임 화면의 방향을 먼저 읽어보겠습니다. 그 기준을 1번 예산편성과 2번 공문 작업대에 적용해 실제로 조작할 수 있는 디자인 시안을 만들겠습니다.


### 진행 안내

붙임 시안의 공통점은 **설명보다 조작하는 판이 먼저 보이고, 목표·힌트·실행 버튼이 한 화면에 모여 있다는 점**이에요. 기존 목업은 카드와 설명이 길게 이어져 업무 안내 페이지처럼 보였습니다.

1번은 칩을 놓는 예산 작업판으로, 2번은 수정할 종이를 직접 만지는 공문 작업대로 바꾸겠습니다. 붙임에서는 화면 구성과 표현 방식만 참고하고, 퍼즐 로직은 가져오지 않겠습니다.


### 진행 안내

두 화면의 조작을 연결했습니다. 예산 화면에서는 사업 카드를 누르면 칩이 배정되고, 단가 인상 연락이 오면 지원을 회수하거나 남긴 칩을 옮길 수 있어요. 공문 화면에서는 수정할 칸을 누르면 관련 자료가 바로 아래에 펼쳐집니다.

이제 휴대폰 크기에서 작업판과 하단 버튼이 얼마나 잘 보이는지, 잘못 가져온 자료를 그 자리에서 고칠 수 있는지 확인하겠습니다.


### 진행 안내

390×844 화면에서는 예산판과 공문·참고자료를 한 화면에 담았습니다. 320px의 작은 화면에서는 작업판 안을 스크롤하되 실행 버튼은 계속 보이게 했어요. 칩 부족, 잘못된 자료 선택, 되돌리기, 기안 완료까지 동작도 확인했습니다.

기존 화면과 새 시안을 나란히 볼 수 있는 비교 페이지를 정리하고 있습니다.

**맞아요. 현재 시안은 게임의 판단보다 정해진 순서를 따라가는 조작에 가깝습니다.** 화면은 게임처럼 바꿨지만, 예산 퍼즐의 재미를 만드는 규칙은 아직 부족해요.

지금 구현된 로직은 이렇습니다.

1. 총 **26칩** 중 제작에 **20칩**을 놓습니다.
2. 남은 6칩으로 지원을 선택합니다.
3. 견적을 받으면 **항상 단가가 올라 제작비가 22칩**이 됩니다.
4. 부족한 2칩을 옮기고, 지원 비용까지 총 26칩 안에 맞추면 완료됩니다.

남은 예산을 반드시 전부 사용할 필요는 없지만, **견적 상승이 고정이고 제작비의 정답도 22칩으로 고정**이라 반복하면 판단할 것이 거의 없습니다. 지원 선택도 이 화면에서는 비용과 설명만 달라져서 재미를 충분히 만들지 못합니다.

칩 옮기기를 살리려면 **‘얼마를 채우느냐’보다 ‘어떤 문제를 감수하고 무엇을 확보하느냐’**가 게임이 되어야 합니다. 예를 들면 다음처럼 바꾸는 거예요. 아래는 새 규칙 제안입니다.

| 선택 | 얻는 것 | 이후 감수할 것 |
|---|---|---|
| 저렴한 인쇄 | 지원에 쓸 예산이 많이 남음 | 검수할 묶음이 많아짐 |
| 검수 포함 인쇄 | 정상본 확보가 쉬워짐 | 배송이나 안내 지원을 포기해야 함 |
| 급행 인쇄 | 일찍 납품받아 배부 시간이 넉넉함 | 예산 여유가 적어 돌발 비용에 취약함 |

시작할 때도 “오늘 분점 배부가 급하다”, “지난번 인쇄 불량이 있었다” 같은 **이번 사업의 단서**를 줘야 합니다. 플레이어는 그 단서를 보고 인쇄 방식과 지원을 고르고, 이후 장면에서 선택의 결과를 겪습니다.

**성공 조건도 ‘제작비 22칩’ 대신 ‘예산 안에서 정상 홍보물 200부를 기한 내 배부하기’로 바꾸는 게 맞습니다.** 여러 계획으로 성공할 수 있고, 남긴 예산도 돌발 상황에 대응하는 가치가 있어야 해요.

현재 방식은 첫 조작을 익히는 짧은 튜토리얼에는 쓸 수 있지만, 독립 퍼즐로는 약합니다. 예산 단계의 핵심 규칙부터 다시 설계해야 합니다.

> “홍보물 200부를 제작해야 합니다. 본관 안내대에서 사용할 견본 하나를 골라 주세요.”

책상에는 **요청 메모, 본관 안내도, 완성 견본 네 개, 안내대, 제작계획 공문**이 놓입니다. 선택 기준은 세 가지입니다.

- 스마트폰 없이도 **종이 안내로 접수창구를 찾을 수 있는가?**
- 지도의 동선이 **본관 안내도와 일치하는가?**
- 안내대에 꽂았을 때 **전화번호가 보이는가?**

**견본마다 실제 시험 결과가 다릅니다**

아래는 제작자용 정답 구조이며, 플레이 화면에서는 직접 발견하게 합니다.

| 견본 | 펼쳐 보면 | 안내대에 꽂으면 | 판단 |
|---|---|---|---|
| 1 | 길 안내가 QR뿐 | 전화번호는 보임 | 스마트폰 없이 길을 찾기 어려움 |
| 2 | 본관과 일치하는 종이 지도 | 전화번호가 앞턱에 가림 | 비치하면 연락처를 확인하기 어려움 |
| 3 | 종이 지도는 있지만 접수창구 위치가 다름 | 전화번호는 보임 | 다른 건물로 안내하는 지도 |
| 4 | 본관과 일치하는 종이 지도 | 전화번호도 보임 | 적합 |

네 견본의 인쇄 품질과 표지는 모두 그럴듯하게 만듭니다. 정답만 눈에 띄게 예쁘거나, 오답에 ‘구버전’ 표시가 붙어 있지는 않습니다.

| 본 자료 → 조작 | 발견 | 선택에 미치는 영향 |
|---|---|---|
| 견본 2 → **펼치기** | 본관과 맞는 종이 지도 | “이걸 쓰면 되겠다”는 첫 가설 |

**재미를 만들려는 지점**

가장 중요한 순간은 **“괜찮다고 생각했는데, 직접 써 보니 문제가 있네?”**입니다.

특히 견본 2는 지도도 맞고 전화번호도 인쇄되어 있습니다. 그런데 안내대에 넣으면 번호가 사라집니다. 이때 정답·오답 팝업을 띄우지 않고, **앞턱이 종이를 가리는 모습 자체**로 발견하게 합니다.

펼치기도 설명창을 여는 동작으로 처리하지 않습니다. 접힌 종이가 열리면서 지도나 QR이 드러나야 합니다. 조작이 관찰 결과를 만들고, 그 결과가 선택을 바꾸는 구조입니다.

**판정과 수정**

공문에는 선택한 견본과 관찰 기록 두 장을 붙입니다.

1. **지도 대조 기록:** 견본 안쪽과 본관 안내도를 함께 보여 줌.
2. **안내대 기록:** 정상적으로 꽂은 상태에서 전화번호를 보여 줌.

완료 판정은 **선정 견본의 세 조건 충족 + 같은 견본의 실제 관찰 근거**로 합니다. 모든 후보를 열었는지, 모든 버튼을 눌렀는지는 검사하지 않습니다.

잘못 제출하면 해당 위치에 짧은 메모가 붙습니다.

- 견본 2: “비치한 상태에서 전화번호를 확인하기 어렵습니다.”
- 견본 3: “이 지도는 본관 접수창구 위치와 다릅니다.”
- 다른 견본의 사진 첨부: “선정 견본과 관찰 대상이 다릅니다.”

초안과 조사 기록은 유지하고, 잘못된 견본이나 근거만 교체합니다.
